## Integration (gsd-integration-checker, static trace)

Connected 14/14, orphaned 1, missing 0.

- The only production write path is `Admin.Keys.generate_key/1`. It seals or refuses with `:key_encryption_not_configured`. Demo seeds and the clean-room bootstrap both go through it.
- All six consumers go through `PrivateJwk.decode` → `to_jwk` → `sign`. No stored private material reaches `JOSE.JWK.from_map` directly.
- `:reject` refuses a row in `decode_stored` before any parser runs. `read_stored` is used only by the reencrypt engine.
- 156's reencrypt and status paths read and write 155's envelopes:
  - `list_signing_key_refs` selects only `{id, kid}`.
  - `reencrypt_signing_key` takes a row lock and does a compare-and-swap.
  - The mix task, doctor and Verify all share `encryption_status/0`.
- JWKS reads select only the public fields, and KeyCache holds only public JWKs.
- The config shape (`keys`/`current`/`legacy_plaintext`), the env var `LOCKSPIRE_KEY_ENCRYPTION_KEY` and the command names are identical across the generator, demo, clean-room, CI and docs.

## E2E Flows (4/4 complete)

1. **Fresh install:** generator block → sealed `generate_key` → token signing → JWKS from public columns.
2. **Absent KEK:** boot still succeeds and legacy rows keep signing. `generate_key` refuses, and doctor and Verify warn.
3. **Upgrade:** plaintext → reencrypt → `--check` → `:reject`, covered by `test/integration/signing_key_upgrade_journey_test.exs`. CI's demo step checks an already-sealed host.
4. **KEK rotation:** rows move to the new KEK id and none remain on the old one (journey test).

## Integration findings (non-blocking)

The checker rated these WARNING. The orchestrator spot-checked each one and none is a live leak:

- **list_keys loads ciphertext:** `list_signing_keys` runs with `sensitive: true` by default (signing_key_store.ex:45), so query telemetry does not carry the bytes. `to_view` strips the column before it reaches a LiveView. This is defense-in-depth only.
- **`decode_with_reason/1` orphaned:** it is `@doc false`, so removing it or wiring it into diagnostics is optional.
- **Legacy-plaintext test fixtures:** they are intentional legacy coverage under test `:allow`. Labelling them, or moving them to the seal helper, is a cleanup task.
- **LSK value guard:** it is a backstop. The key-name drop lists cover `private_jwk_encrypted` and `private_jwk`.
- **CHANGELOG link and entry:** the entry is created at release by Release Please from the squash title in `157-RELEASE-NOTES.md`.
