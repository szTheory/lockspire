# v1.35 CI/CD Audit Summary

**Date:** 2026-06-30  
**Decision:** Optimize CI by removing duplication and adding missing compatibility signal before adding sharding or heavier automation.

## Evidence

- CI already had high-value gates: format, compile warnings, tests, QA/security, adoption smoke, release hygiene.
- A separate Sobelow/static security step duplicated work already run by `mix qa`.
- Dialyzer PLTs were not cached in the fast-check workflow.
- Minimum supported Elixir/OTP compatibility was not explicit as a first-class job.
- Release workflow cache keys were less precise than the CI cache keys.

## Implemented Fix

- Added explicit latest/minimum Elixir and OTP env values.
- Added Dialyzer PLT cache keyed by OS, OTP, Elixir, `mix.exs`, and `mix.lock`.
- Removed duplicated static security step.
- Added minimum supported Elixir/OTP compatibility job.
- Tightened release workflow setup-beam and cache keys.

## Not Worth Doing Yet

- Test sharding: wait for measured CI p95 evidence.
- Coverage upload on every PR: not enough signal for the runtime cost yet.
- Full Docker Compose adoption-demo smoke in CI: keep the deterministic Python smoke as the CI proof.
