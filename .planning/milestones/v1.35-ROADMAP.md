# Milestone v1.35: CI/CD Efficiency And Release Hygiene

**Status:** IMPLEMENTED IN WORKTREE 2026-06-30
**Focus:** Remove duplicated low-value CI work, add explicit compatibility signal, and tighten release/package confidence.

## Overview

v1.35 keeps CI boring. The pipeline gets better signals with less duplication: exact-version release setup, precise cache keys, a minimum supported Elixir/OTP test job, Dialyzer opt-in until the baseline is clean, and package hygiene guards.

## Delivered

- `.github/workflows/ci.yml` now defines latest and minimum Beam versions explicitly.
- Fast checks stop running the known-noisy Dialyzer baseline as a mandatory PR gate.
- Duplicate Sobelow/static security step was removed because `mix qa` already runs the security gate.
- A `compatibility` job runs compile and fast tests on minimum supported Elixir/OTP.
- `.github/workflows/release.yml` now uses explicit Elixir/OTP env values and cache keys that include OS, OTP, Elixir, and lockfile.
- Release-readiness contracts catch broad package globs that would include `priv/plts`, `.DS_Store`, or `.bak` artifacts.

## Open Follow-Up

- Collect real GitHub Actions p50/p95 job timings after this lands.
- Only add partitions or sharding after measured suite time shows the critical path justifies the complexity.
- Consider a scheduled broad compatibility matrix later if adopter evidence shows version drift risk beyond minimum/latest.
