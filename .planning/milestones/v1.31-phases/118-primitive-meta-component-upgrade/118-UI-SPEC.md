# Phase 118 — UI Design Contract

> Visual and interaction contract for Phase 118: Primitive & Meta-Component Upgrade. Generated by gsd-ui-researcher for planner, executor, checker, and auditor use.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none; Phoenix function components plus embedded `lockspire-admin-*` CSS |
| Preset | not applicable |
| Component library | Lockspire-owned `Lockspire.Web.Components.AdminComponents` |
| Icon library | none for this phase; status meaning uses text plus shape/non-color cue |
| Font | `--ls-font-display` Familjen Grotesk stack for headings; `--ls-font-sans` Inter stack for UI/body; `--ls-font-mono` JetBrains Mono stack for identifiers |
| CSS architecture | BEM/design-token `lockspire-admin-*`; no Tailwind, shadcn, public theming engine, or host-editable registry |
| Runtime shape | Phoenix function components with explicit `attr` and `slot`; LiveComponents only for concrete local state plus event handling |

Sources: `.planning/STATE.md`, `.planning/REQUIREMENTS.md`, `118-CONTEXT.md`, `brandbook/`, `lib/lockspire/web/admin_css.ex`, `lib/lockspire/web/components/admin_components.ex`.

## Visual Language

Phase 118 must make the admin UI read as structured trust: calm, dense, precise operator workflows composed from reusable panes, headers, rows, status/action clusters, and workflow shells. The phase strengthens building blocks; it does not redesign the admin shell or create marketing-style surfaces.

Required visual qualities:

- Surfaces stay quiet and work-focused: muted page background, white/dark panels, restrained borders, compact rows, and clear hierarchy.
- The primary visual anchor for upgraded admin compositions is the `entity_header` title/status/action cluster, followed by pane headings and lifecycle rows.
- Signal Cyan remains restrained. Use Deep Cyan `#0e7490` for light-mode action text/fills and Signal Cyan `#22d3ee` for dark-mode accent, focus, logo, and large non-text signal only.
- No decorative security tropes: no shields, threat maps, novelty console styling, panic language, or generic cyber visuals.
- Components must tolerate generated long values, dense scopes, repeated badges, and destructive clusters without horizontal page overflow.

## Spacing Scale

Declared values are the existing 4px baseline token scale:

| Token | Value | Usage |
|-------|-------|-------|
| `--ls-space-1` | 4px | Dot gaps, required-marker gaps, tight inline rhythm |
| `--ls-space-2` | 8px | Badge gaps, help/error stack gaps, compact control padding |
| `--ls-space-4` | 16px | Default element spacing, form/filter padding, metric padding, button clusters, row metadata gaps, compact section padding |
| `--ls-space-6` | 24px | Section/card padding and ordinary page group gaps |
| `--ls-space-8` | 32px | Page body padding and page-hero padding |
| `--ls-space-12` | 48px | Empty-state vertical padding and major group breathing room |
| `--ls-space-16` | 64px | Largest structural page breathing room when a primitive needs explicit major separation |

Exceptions:

- Existing legacy tokens or CSS values at 12px, 20px, and 40px may remain only as compatibility values already shipped in current CSS. They are not active Phase 118 spacing choices and must not be used for new primitive, meta-component, or lab spacing declarations.
- Control minimum height stays `--ls-control-height: 40px` because it is already shipped. Do not introduce smaller interactive targets.
- Badge pill radius may remain `9999px`; cards and panels stay at `--ls-radius-lg` or less unless existing CSS already uses the token.
- Dense rows may reduce internal gap to `--ls-space-2` only when long values still wrap and focus remains visible.

## Typography

Use exactly these shipped type roles for new or upgraded primitives:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px (`0.75rem`) | Semibold 600 | 1.2 |
| Body | 14px (`0.875rem`) | Regular 400 | 1.5 |
| Heading | 16px (`1rem`) | Semibold 600 | 1.25 |
| Display | 24px (`1.5rem`) | Semibold 600 | 1.2 |

Rules:

- Do not add new font files or external font fetches.
- Keep operator data, IDs, URLs, handles, token-like values, timestamps, and code in the mono stack through `long_value`, `timestamp`, code blocks, or equivalent.
- Avoid viewport-scaled type. Text must wrap within controls and rows instead of shrinking with viewport width.
- Existing legacy `700` or `650` weights may remain where already shipped, but Phase 118 primitives must expose only regular 400 and semibold 600.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ls-surface-page` light `#f8fafc`, dark `#0b1220` | Page background and broad admin shell |
| Secondary (30%) | `--ls-surface-panel` light `#ffffff`, dark `#131c2e`; `--ls-surface-muted` | Cards, panes, rows, filters, empty states, form shells |
| Accent (10%) | Light `--ls-text-accent` / Deep Cyan `#0e7490`; dark Signal Cyan `#22d3ee` | Primary buttons, text links, active nav underline, focus ring, restrained status/info border |
| Destructive | `--ls-status-danger-*` semantic aliases | Destructive buttons, destructive confirmation panels, validation/error states, terminal security failures |

Accent reserved for:

- Primary CTA buttons.
- Text links and active secondary/current nav state.
- Focus rings and focus glows.
- Dark-mode primary button fill.
- Non-text brand/signal accents where contrast is preserved.

Accent must not be used for generic decoration, normal light-mode body text, small light-mode icons with low contrast, or every interactive element.

## Status Semantics

`status_badge` must become domain-aware while preserving current call sites. Keep `status={...}` working; add `domain={...}` or `context={...}` for ambiguous statuses. No real Configure, Support, or Operate status may fall through to disabled styling.

Required tone set:

| Tone | CSS family | Meaning | Statuses that must map intentionally |
|------|------------|---------|--------------------------------------|
| `:healthy` | success / active | Current, allowed, available | `:active`, `:open`, `:approved` when device auth is approved-but-waiting must include waiting copy if context requires |
| `:waiting` | info | Pending protocol or queue work | `:pending`, `:pending_login`, `:pending_consent`, `:enqueued`, `:attempted`, device auth `:approved` |
| `:warning` | warning | Operator attention or non-terminal risk | `:retiring`, `:retryable`, `:denied` |
| `:danger` | danger | Security incident or terminal operational failure | `:reuse_detected`, `:discarded` |
| `:disabled` | neutral muted | Intentionally disabled or retired, not unknown real state | `:disabled`, `:retired` |
| `:completed` | success or completed semantic class | Finished/consumed state | `:completed`, `:consumed`, `:used`, `:succeeded`, `:rendered`, `:skipped` |
| `:provenance` | info/provenance semantic class | Origin, not health | `:operator`, `:self_registered`, `:self_registered_client`, `:system`, `:host_app`, `:dcr`, `:one_time`, `:remembered`, `:initial_access_token` |

Additional required mappings:

- `:upcoming` remains informational.
- `:revoked` remains danger unless a local context proves revoked is a routine closed state; text must still say `Revoked`.
- `:expired` is closed/disabled only when time has elapsed; it must not imply a disabled control state.
- Unknown values may keep the disabled fallback only when the test proves the fallback is for truly unknown statuses.

Badge contract:

- Badge labels must be human-readable and stable.
- Every badge includes text and the existing dot/shape cue; color alone is never the only meaning.
- The title/tooltip, if added, must clarify context without replacing visible text.
- Light/dark/system must use semantic `--ls-status-*` aliases, not raw one-off colors.

## Component Contracts

All new or upgraded components live in `Lockspire.Web.Components.AdminComponents` unless implementation proves a narrower helper is cleaner. Components render structure and chrome only; LiveViews keep URL state, loading state, mutations, validation semantics, and OAuth/OIDC policy.

| Component | Required contract |
|-----------|-------------------|
| `pane` / architectural pane | Slot-based section for grouped admin content with title, subtitle/help, optional actions/status, and `class`; maps to panel/card CSS without nested-card layouts. |
| `entity_header` | Header for one client/token/consent/key/work item with eyebrow, title, subtitle, optional long identifier, status cluster, and action cluster. Must support very long IDs and missing subtitle. |
| `workflow_shell` | Wrapper for configuration/destructive/copy-once workflows with optional error summary, help text, body slot, action slot, and form slot. It must not hide `phx-change`, `phx-submit`, IDs, names, or changeset behavior. |
| `status_cluster` | Semantic grouping for repeated badges and small state text. Must wrap without shifting row layout and allow repeated badges. |
| `action_group` upgrade | Preserve primary/secondary/destructive slots. Destructive slot remains visually separated. Disabled link actions render as non-clickable `role="link" aria-disabled="true"` and keep visible disabled styling. |
| `lifecycle_row` | Row for lifecycle states/actions: label/title, state badge, timestamp, actor/source, optional consequence copy, optional actions. Must handle destructive actions and redacted handles. |
| `dense_resource_row` | Compact alternative to `resource_item` for Support/Operate data: title, subtitle, metadata slots, long values, status, actions. Must support dense filters and queue rows without table overflow. |
| `responsive_table` / table-list alternative | Tables remain for comparison; component must provide a list/card alternative or responsive wrapper for narrow widths. Empty state is required for zero rows. |
| `form_field` upgrade | Preserve current label/help/error/required/inner block API. It must own help/error IDs and expose enough hooks for inputs to use `aria-describedby` and `aria-invalid`. |
| `empty_state` upgrade | Preserve title/body. Add optional actions slot only if it improves next safe action clarity. Empty states must name what is absent and the next safe step. |
| `confirmation_panel` upgrade | Preserve title/variant/errors/body/actions. Destructive variants must state durable consequence and support action groups. |
| `long_value` | Continue to wrap IDs, URLs, token handles, timestamps, and mono values. Redacted values show `Redacted`; no secret plaintext in tests/docs/screenshots. |

Backward compatibility:

- Do not remove or rename current primitives: `page_hero`, `filter_bar`, `resource_item`, `action_group`, `status_badge`, `form_field`, `confirmation_panel`, `empty_state`, `copy_once_secret_panel`, `long_value`, `badge_group`, `section_card`, `metric_grid`, `summary_stat`, `description_list`, `policy_nav`, `timestamp`, `error_summary`, `admin_button`.
- Prefer additive attrs/slots and wrapper components.
- Existing production call sites must compile without migration.

## Interaction States

Required states for all relevant primitives:

- Default, hover, active, focus-visible, disabled, readonly, invalid, empty, error, destructive, loading-by-parent, long-value, dense-data.
- Motion uses explicit transition properties only: 150ms fast feedback, 220ms medium if needed, standard easing. No `transition: all`.
- Reduced motion must neutralize transform/transition duration through existing tokens and media behavior.
- Focus rings remain visible, offset, and contrast-safe on buttons, links, filter fields, secondary nav, resource rows, destructive controls, and long-value affordances.
- Disabled links must not navigate and must expose `aria-disabled="true"`.
- Destructive action groups must keep destructive actions visually separated from primary/secondary actions on desktop and stacked with a top separator on narrow screens.
- Copy-once flows may show plaintext only at creation time and only via copy-once panels; follow-up states must render redacted placeholders or handles.

## Form And Workflow Contract

Shared form primitives must be used wherever practical in production forms and filters:

- `form_field` owns label, help copy, required marker, field error list, and deterministic help/error IDs.
- Pages still render Phoenix inputs/selects/textareas explicitly so names, IDs, values, `to_form`/changeset behavior, `phx-change`, and `phx-submit` remain visible to maintainers.
- User-correctable validation should pair `error_summary` with field-level errors.
- Inputs with field errors use `aria-invalid="true"` only after validation and connect help/error copy with `aria-describedby`.
- Filter bars may use shared field wrappers when it does not reduce readability; dense filter exceptions must be named in tests.

Allowed documented exceptions:

- Complex checkbox confirmations.
- Lifecycle action forms with unusual confirmation copy.
- Copy-once secret/RAT/IAT flows where wrappers obscure the one-time security boundary.
- Existing LiveComponents that genuinely need local state plus event handling.

Every exception must be covered by focused rendered assertions or LiveView tests that prove labels, help/error text, accessibility hooks, and redaction boundaries.

---

## Responsive Behavior

Responsive contract:

- No page-level horizontal overflow at 320px, 390px, 768px, 1024px, or 1440px after Phase 119/120 browser proof.
- Phase 118 component stress proof must include narrow-safe structures even though mounted browser proof belongs to Phase 120.
- Resource rows and dense rows must wrap metadata and actions; long values use `overflow-wrap: anywhere` or equivalent via `long_value`.
- Table alternatives must avoid raw table drift for Support and Operate pages. If a true comparison table remains, it must sit in `lockspire-admin-table-wrap` and have a list alternative where practical.
- Secondary navigation and dense filters wrap or scroll intentionally without clipping text or controls.

---

## Accessibility

Phase 118 must preserve the existing WCAG floor:

- AA contrast for text and non-text controls in light, dark, and system modes.
- Status meaning never relies on color alone; badge text plus dot/shape cue is required.
- Focus is visible on all keyboard-reachable controls and links.
- Form help/error text is programmatically associated with inputs when user-correctable.
- Error summaries use `role="alert"` and are focusable when rendered.
- No duplicate IDs in generated form/field examples.
- Disabled links expose disabled semantics and are not keyboard-activatable.
- Destructive confirmations name the durable consequence before the destructive action.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Apply filters` for filter/action proof; preserve domain CTAs such as `Mint initial access token`, `Register client`, `Revoke token family` where already specific |
| Empty state heading | `No {resource} match this view` for filtered lists; `No {resource}` for true empty queues |
| Empty state body | `Adjust the filters or return to the overview to choose a different {journey} workflow.` For true empty queues: `There are no {workflow records} waiting for operator review.` |
| Error state | `Review the highlighted fields` with field-specific repair copy such as `Enter a registered redirect URI.` |
| Destructive confirmation | `{Action name}: This action {durable consequence}. Type/confirm the required identifier before continuing.` |
| Disabled action copy | Label the unavailable action directly; do not suggest it can be retried unless an existing domain API backs it. |
| Copy-once copy | `Copy this value now. Lockspire stores only the hash after this response.` |

Tone rules:

- Calm, precise, consequence-oriented.
- Use OAuth/OIDC nouns: client, consent grant, token family, initial access token, registration access token, device authorization, interaction, logout delivery.
- Do not use fear language, generic security tropes, or vague CTAs such as `Submit`, `Continue`, or `Go`.

Destructive actions in scope:

- Revoke consent grant: names grant revocation consequence.
- Revoke token: names access/refresh token effect.
- Revoke token family: names family-wide refresh-token invalidation.
- Revoke initial access token: names DCR intake impact.
- Disable client / enable client / rotate secret / rotate registration access token / key publish-activate-retire actions: keep existing domain semantics; new primitives may group them but must not invent new operations.

## Test And Stress Scenarios

Phase 118 proof must extend the internal lab and rendered tests, not a public route.

Required stress coverage:

- Disabled links.
- Destructive action groups with separated destructive slot.
- Dense filters using shared field/help/error primitives where practical.
- Secondary navigation wrapping/focus behavior.
- Empty tables and empty list alternatives.
- Repeated badges in a status cluster.
- Generated long values: client IDs, account handles, URLs, scopes, token handles, key IDs, thumbprints, timestamps.
- Domain-aware status semantics for Configure, Support, and Operate statuses.
- Unknown status fallback remains disabled and is covered as unknown-only behavior.
- Form/workflow primitives with help IDs, error IDs, `aria-describedby`, and `aria-invalid`.
- Redaction absence across fixture data and rendered HTML.

Proof files:

- `test/support/lockspire/web/admin_lab/fixtures.ex`
- `test/support/lockspire/web/admin_lab/stress_surface.ex`
- `test/lockspire/web/live/admin/design_system_component_stress_test.exs`
- `test/lockspire/web/live/admin/design_system_contract_test.exs`

Assertion style:

- Prefer focused rendered assertions over wholesale snapshots.
- Assert user-visible labels, stable `lockspire-admin-*` classes, semantic status mappings, accessibility hooks, redaction boundaries, and fixture coverage.
- Keep lab classified as `test_only` / `internal_lab`; do not mount it through `Lockspire.Web.AdminRouter`.
