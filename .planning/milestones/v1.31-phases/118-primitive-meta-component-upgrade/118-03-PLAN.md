<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator input -> LiveView form validation | User-correctable validation crosses into field and summary rendering. |
| Form primitive -> production call site | Shared chrome must not hide IDs, names, form events, or mutation policy. |
| Sensitive workflow -> rendered UI | Secret/token/key/user-code flows must preserve redaction and copy-once boundaries. |
| Disabled/destructive action -> operator behavior | UI must truthfully represent unavailable or destructive actions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-06 | Tampering | `form_field`, production forms | mitigate | Assert deterministic help/error IDs, `aria-describedby`, and `aria-invalid` only for validated invalid state per D-17. |
| T-118-01 | Information Disclosure | copy-once and token workflows | mitigate | Keep exception inventory and redaction assertions for secret/RAT/IAT/token/key/user-code surfaces per D-18. |
| T-118-02 | Tampering | form/workflow primitive APIs | mitigate | Use additive attrs/slots only and preserve legacy component names per D-05. |
| T-118-04 | Spoofing | disabled/destructive actions | mitigate | Assert disabled links are non-clickable and destructive actions are separated/named with durable consequences. |
| T-118-SC | Tampering | Package installs | accept | Phase 118 installs no npm, pip, cargo, or Hex packages; package legitimacy gate is not triggered. |
</threat_model>
