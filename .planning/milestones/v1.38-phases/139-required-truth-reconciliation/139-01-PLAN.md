<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| CLI arguments -> acceptance authority | Caller-supplied SHA, deadlines, formats, and dispositions are untrusted until strict parsing and repository equality. |
| Git/GitHub observations -> PASS | Local refs and remote JSON are mutable evidence and require exact identity, completeness, and before/after checks. |
| Workflow/job response -> receipt | Only allowlisted scalar fields cross into deterministic JSON; raw responses remain private. |
| mix ci process -> local-gate result | Exit status, proof of executed tests, and unchanged HEAD jointly control PASS. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-139-01 | Spoofing | canonical CI and Release run selection | high | mitigate | Filter by exact SHA, validate workflow/repository/event/branch/status/conclusion/run id, and reject zero or ambiguous candidates. |
| T-139-02 | Tampering | local/main identity during long gates | high | mitigate | Compare HEAD, local main, and fetched origin/main before and after mix ci and polling. |
| T-139-03 | Repudiation | compact acceptance receipt | medium | mitigate | Emit deterministic schema, SHA, run ids, events, conclusions, URLs, job outcomes, and WARN dispositions. |
| T-139-04 | Information disclosure | API and command diagnostics | medium | mitigate | Allowlist receipt fields and use bounded class-only errors without raw bodies, secrets, or environment values. |
| T-139-05 | Denial of service | workflow polling | low | accept | A caller-bounded deadline and stable run id make temporary GitHub latency tolerable without an unbounded wait. |
| T-139-06 | Elevation of privilege | Release no-publish evaluation | critical | mitigate | Require push event plus skipped protected jobs and provide no dispatch or publication command. |
</threat_model>
