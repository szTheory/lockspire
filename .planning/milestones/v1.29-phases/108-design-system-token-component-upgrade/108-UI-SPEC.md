# Phase 108 — UI Design Contract

> Visual and interaction contract for Phase 108. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 108 upgrades the Lockspire admin design-system foundation. It does not redesign weak support and operations pages, introduce Tailwind or shadcn, create a host theming layer, or change the host-owned authentication, layout, branding, and tenant-policy seam.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Phoenix function components in `Lockspire.Web.Components.AdminComponents`; no external UI registry |
| Icon library | none for Phase 108; keep text labels visible for operator actions |
| Font | System sans via `--ls-font-sans`; mono via `--ls-font-mono` for IDs, timestamps, URLs, token family identifiers, and redacted values |

### Implementation Boundary

- Keep `Lockspire.Web.Admin.CSS` as the single embedded admin CSS and token source.
- Keep all admin classes under the `lockspire-admin-*` namespace.
- Keep Phoenix component APIs backward-compatible; add explicit `attr` and `slot` declarations for new reusable primitives.
- Preserve page-owned URL state and workflow intent in LiveViews; components render structure, state, actions, and safety treatment only.
- Do not add Tailwind, shadcn, copied host CSS assets, generated host-editable components, a theme engine, or third-party component registries.

### Required Component Primitives

| Primitive | Contract |
|-----------|----------|
| `page_hero` | Renders eyebrow, title, supporting copy, optional summary/action slot, and uses the hero focal point contract below. |
| `metric_grid` / metric item | Renders 2-4 operator metrics with tabular values and compact labels; wraps without changing card height assumptions. |
| `task_card` / `attention_card` | Renders journey/task title, state cue, short body, and one specific next-action label. |
| `filter_bar` | Renders compact filter controls, result count/help text, and reset/apply actions without taking ownership of URL state. |
| `resource_item` / responsive row | Renders title, subtitle, metadata, status cluster, and actions; long values must wrap within the row. |
| `copy_once_secret_panel` | Renders client secrets, IAT plaintext, and RAT plaintext with one-time visibility copy and redaction-safe structure. |
| `action_group` | Groups primary, secondary, and destructive actions; destructive actions are visually separated and confirmation-backed. |
| `empty_notice` / `empty_state` | Renders a specific empty heading, body, and next safe action or pivot route. |
| `long_value` | Renders IDs, URLs, token family identifiers, subject/client IDs, and timestamps with `overflow-wrap:anywhere` and mono/tabular treatment where appropriate. |

## Visual Hierarchy

| Surface | Focal Point | Secondary Priority | Avoid |
|---------|-------------|--------------------|-------|
| Token/component foundation | The reusable primitive or token category being applied | Evidence that old raw markup now maps to a shared primitive | Decorative panels, broad page redesigns, visual novelty |
| Strong baseline routes | Existing hero, metric, task, and security posture patterns | Behavior-neutral markup replacement | Re-litigating v1.28 route IA |
| Weak-page preparation | Row, filter, long-value, status, and action primitives that Phase 109 can reuse | Mobile wrapping and safety affordance hooks | Redesigning interactions, device authorizations, logout deliveries, tokens, consents, or IATs in Phase 108 |

The primary visual anchor for shared admin screens is: page hero title and task/state summary first, primary route action second, dense diagnostic details third.

Icon-only actions are not allowed in Phase 108. If a future route adds icons, the text label remains visible or an accessible name is provided and tested.

## Spacing Scale

Declared values:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tiny inline spacing, badge internals |
| sm | 8px | Compact control gaps and label-to-field spacing |
| md | 16px | Default component padding and list gaps |
| lg | 24px | Section padding, hero internals, card stacks |
| xl | 32px | Page body padding and major grid gaps |
| 2xl | 48px | Major section breaks and empty-state vertical padding |
| 3xl | 64px | Reserved page-level rhythm; use sparingly |

Exceptions: none.

Migration rule: move existing `--ls-space-*` tokens toward this public semantic scale. Intermediate legacy aliases may remain only as private compatibility aliases when needed to keep behavior-neutral migrations small, but new component contracts must use the declared semantic spacing tokens.

Control sizing:

- Standard text buttons and inputs: minimum height 40px.
- Dense badge and metadata clusters: minimum visual height may be smaller, but click targets stay on surrounding row/action controls.
- Mobile action groups: stack vertically and stretch buttons to container width.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 600 | 1.2 |
| Body | 14px | 400 | 1.5 |
| Heading | 16px | 600 | 1.25 |
| Display | 24px | 600 | 1.2 |

Rules:

- Use exactly these four component-level sizes for new Phase 108 primitives.
- Use exactly two weights: 400 and 600. Existing heavier shell/page values should be normalized through typography tokens when touched.
- Letter spacing is `0` for normal copy. Uppercase labels may use `0.05em`.
- Body copy, help text, empty states, alerts, and confirmation panels use sentence case and calm operator language.
- Mono text is reserved for identifiers, URLs, timestamps, token family IDs, code blocks, and redacted/copy-once values.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f9fafb` | Admin shell background and quiet page surfaces |
| Secondary (30%) | `#ffffff` | Cards, hero panels, confirmation panels, and primary content surfaces |
| Accent (10%) | `#2563eb` | Primary CTA background, current nav indicator, focused link/title affordance, focus ring |
| Destructive | `#991b1b` | Destructive action text, destructive badges, destructive confirmation copy |

Accent reserved for: primary CTA background, current nav indicator, resource title links, focused controls, and the single most important route action. Routine secondary links, table controls, and metadata affordances use neutral text/border tokens.

Semantic status colors are distinct from accent:

| Status | Contract |
|--------|----------|
| Success | Healthy, active, completed, published, or safe-copy success state. |
| Warning | Attention-worthy but reversible state such as expiring, retrying, retiring, or policy exception pressure. |
| Danger | Reuse detected, revoked, failed, discarded, disabled-risk, or destructive confirmation state. |
| Info | Neutral upcoming, pending, or explanatory state. |

Token migration rule: raw hex values may appear in token declarations only. Existing alert, confirmation, status, focus, and border colors should move behind semantic `--ls-*` tokens before stricter raw-hex tests are added.

## Motion And Reduced Motion

Motion is CSS-only in Phase 108 and must serve feedback, focus/hover affordance, or state continuity.

| Token | Value | Usage |
|-------|-------|-------|
| `--ls-motion-duration-fast` | 150ms | Hover, focus, border, background, and shadow feedback |
| `--ls-motion-duration-medium` | 220ms | Reserved for future disclosure or flash continuity |
| `--ls-motion-ease-standard` | `cubic-bezier(0.4, 0, 0.2, 1)` | Default easing |

Rules:

- Remove the current bouncy transition concept from the public contract.
- Avoid decorative transform motion. Pressed-button scale may remain only if reduced-motion neutralizes it.
- Under `@media (prefers-reduced-motion: reduce)`, transition and animation duration must be near-zero and active transforms must be disabled.
- Do not add a broad LiveView JS animation layer. Targeted `Phoenix.LiveView.JS` transitions remain future work only when a page workflow needs them.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Upgrade design-system primitives |
| Empty state heading | No reusable primitive is defined yet |
| Empty state body | Add the shared component or token before polishing this route-specific markup. |
| Error state | Design-system contract failed. Review the flagged token, component, or class rule and update the shared primitive before changing route markup. |
| Destructive confirmation | Remove unsafe one-off styling: confirm that the route now uses the shared component and no longer renders raw layout or secret markup. |

Copy rules:

- Primary actions use a verb plus noun: "Create initial access token", "Rotate client secret", "Review logout deliveries", "Upgrade design-system primitives".
- Empty states explain what is absent and provide the next safe route/action.
- Error states name the failed contract and the next fix path.
- Destructive or irreversible actions must declare consequence and reversibility in the confirmation panel.
- Copy-once material must never be logged, documented as raw evidence, or repeated outside the reveal panel.

## Interaction And State Contracts

| Pattern | Contract |
|---------|----------|
| Buttons and links | Primary/secondary/danger variants remain visually distinct; disabled state uses `aria-disabled` for links and `disabled` for buttons. |
| Focus | Focus rings use the accent token and remain visible on nav items, links, buttons, form controls, and resource rows. |
| Filters | Filter bars expose current criteria, result count/help text, and reset/apply actions; URL state remains LiveView-owned. |
| Rows/lists | Rows support title, subtitle, metadata, status badges, and actions without page-level horizontal overflow. |
| Tables | Tables remain allowed for dense operational data, but Phase 108 must provide row/list/table primitives so Phase 109 can choose route-specific IA. |
| Secrets | Copy-once secret panels show plaintext only immediately after creation/rotation and otherwise render redacted state. |
| Confirmations | Dangerous actions use danger button treatment plus confirmation copy that names the affected client, token family, consent, key, or delivery when available. |
| Long values | Long identifiers, URLs, timestamps, subjects, clients, token families, and delivery IDs wrap within their container and do not overlap adjacent controls. |

---

## Mobile Contract

- Hero, metric grids, resource rows, filter bars, action groups, and confirmation actions must collapse to one-column layouts below 720px.
- Buttons in stacked mobile action groups stretch to full width.
- Long values use `overflow-wrap:anywhere`; mono text must not force page-level horizontal scrolling.
- Horizontal table scrolling may remain as a compatibility fallback, but Phase 108 must not make it the only long-term primitive for support and operations incident pages.
- Text must not overlap badges, actions, or preceding/subsequent content on mobile.

## Contract Fences

Primary deterministic fence: `test/lockspire/web/live/admin/design_system_contract_test.exs`.

Add or extend tests for:

- Required semantic token categories: surface, text, border, status, spacing, control size, radius, shadow, typography, focus, z-index, and motion.
- Reduced-motion behavior and active-transform neutralization.
- Namespaced `lockspire-admin-*` classes for all shared primitives.
- No inline layout styles in admin LiveViews.
- Raw hex colors outside token declarations.
- Canonical shared primitive/class coverage for hero, metric, task/attention card, filter bar, resource row, empty state, confirmation panel, copy-once secret panel, long-value display, status cluster, and action group.
- Small rendered component assertions for structural contracts only; avoid brittle full HTML snapshots.

Browser screenshots, route-wide click-through, final mobile overflow proof, and visual regression proof remain Phase 110 scope.
