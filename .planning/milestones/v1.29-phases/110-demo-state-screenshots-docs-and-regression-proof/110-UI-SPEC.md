# Phase 110 - UI Design Contract

> Visual and interaction contract for Phase 110. Generated by gsd-ui-researcher inline fallback, verified by gsd-ui-checker inline fallback.

Phase 110 proves the final v1.29 admin route surface. It expands demo state, captures desktop/mobile screenshots, updates operator docs, runs browser click-through evidence, and pins deterministic regression tests. It must not redesign admin routes, broaden protocol scope, introduce a UI framework, or change the host-owned staff-auth, layout, branding, MFA, role, tenant-policy, or product-authorization seam.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Phoenix function components in `Lockspire.Web.Components.AdminComponents`; no external UI registry |
| Icon library | none for Phase 110 proof; operator actions keep visible text labels |
| Font | System sans via `--ls-font-sans`; mono via `--ls-font-mono` for IDs, URLs, timestamps, command output, screenshot file names, and redacted demo values |

### Implementation Boundary

- Preserve `Lockspire.Web.Admin.CSS` as the single embedded admin CSS source and keep all admin classes under `lockspire-admin-*`.
- Treat Phase 107 route journey vocabulary, Phase 108 shared primitives, and Phase 109 weak-page polish as locked inputs.
- Use Phase 110 implementation work for demo data, docs, screenshots, browser evidence, screenshot inventory, and regression fences only.
- Do not add Tailwind, shadcn, third-party component registries, a theming engine, screenshot-only CSS, inline layout styles, decorative motion, or new protocol behavior.
- Do not expose client secrets, access/refresh token plaintext, IAT plaintext after creation, RAT plaintext after rotation, user codes, verifier material, or real-looking credentials in demo seeds, screenshots, docs, logs, or browser evidence.

## Visual Hierarchy

Primary visual anchor: final proof that each route's journey label, operator job statement, attention-worthy state, and next safe action survive realistic demo data at desktop and mobile widths.

| Surface | Focal Point | Secondary Priority | Avoid |
|---------|-------------|--------------------|-------|
| Demo seed output | The operator state being exercised: healthy, warning, incident, disabled, self-registered, retryable, revoked, expired, long-value, copy-once | Non-secret identifiers that make screenshot inspection useful | Real-looking secrets, random filler, undocumented fixture-only states |
| Screenshots | Journey label, page job copy, state summary, primary action, long-value wrapping | Route-specific row/card/detail evidence and empty/risk state coverage | Cropped proof that hides nav, state, or mobile overflow |
| Operator docs | Orient / Configure / Support / Operate journey model and host-owned boundary | Subordination to `docs/supported-surface.md` and route-specific proof links | Product-marketing tone, standalone-service framing, host-owned auth promises |
| Browser click-through | Operator can navigate from overview to each route and complete safe read-only paths | Focus-visible controls, no page-level horizontal overflow at 390px, redaction visible where needed | Relying only on static source assertions for visual proof |
| Regression tests | Deterministic fences for journey, primitives, motion, inline style, screenshots, docs, and inventory | Fast failure messages that name the drifted route or contract | Brittle full-page snapshots or visual assertions that cannot be maintained |

Icon-only actions are not allowed in Phase 110 proof. If any compact control exists, the visible screenshot and docs evidence must show a nearby text label or tested accessible name.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tiny inline gaps, screenshot inventory metadata separators, badge internals |
| sm | 8px | Compact control gaps, label-to-value spacing, browser evidence table internals |
| md | 16px | Default row/card/list padding, proof artifact table spacing, screenshot note spacing |
| lg | 24px | Page section padding, docs section spacing, confirmation panels |
| xl | 32px | Major layout gaps and mobile stacked proof sections |
| 2xl | 48px | Empty-state screenshot breathing room and major route-group breaks |
| 3xl | 64px | Reserved page-level rhythm only; use sparingly |

Exceptions: none.

Control sizing:

- Standard buttons, links styled as buttons, and inputs keep a minimum 40px height.
- Mobile action groups stack vertically and stretch controls to container width.
- Screenshot inventory and docs tables may be dense, but admin route content still uses the approved component spacing and must not overlap at 390px.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 600 | 1.2 |
| Body | 14px | 400 | 1.5 |
| Heading | 16px | 600 | 1.25 |
| Display | 24px | 600 | 1.2 |

Rules:

- Use exactly these four admin UI sizes and exactly two weights, 400 and 600, for new Phase 110 admin-facing markup or proof-specific UI fragments.
- Documentation headings may use Markdown defaults, but route copy quoted into docs must preserve the approved journey vocabulary and verb-plus-noun action labels.
- Letter spacing is `0` for normal copy. Existing uppercase labels may use `0.05em` only where the admin design system already uses that pattern.
- Mono text is reserved for identifiers, URLs, timestamps, screenshot paths, command names, command output snippets, and redacted values.
- Long mono values in screenshots must use `long_value` or equivalent `overflow-wrap:anywhere` treatment.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f9fafb` | Admin shell background, quiet proof surfaces, screenshot inventory background |
| Secondary (30%) | `#ffffff` | Cards, hero panels, filter bars, confirmation panels, primary content surfaces |
| Accent (10%) | `#2563eb` | Primary CTA background, current nav indicator, resource title links, focused controls, selected route/proof anchor |
| Destructive | `#991b1b` | Destructive action text, destructive badges, destructive confirmation copy, revocation/retirement/discard proof states |

Accent reserved for: primary CTA background, current nav indicator, resource title links, focused controls, selected route/proof anchor, and the single most important route action. Accent must not be used for all links, every badge, decorative screenshot annotations, or routine secondary actions.

Semantic status colors remain separate from accent:

| Status | Contract |
|--------|----------|
| Success | Healthy, active, completed, published, copied, current, verified screenshot or browser proof |
| Warning | Waiting, retrying, expiring, retiring, pending too long, disabled policy pressure, exception pressure, missing proof inventory item |
| Danger | Failed, discarded, reuse detected, revoked, expired when incident-worthy, disabled-risk, destructive confirmation state |
| Info | Neutral pending, upcoming, explanatory proof guidance, browser note, screenshot metadata |

Status badges must include text labels; color alone is never the only state cue.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Capture admin proof |
| Empty state heading | No screenshot evidence recorded yet |
| Empty state body | Run the admin screenshot capture for this route, then record the desktop path, mobile path, journey, demo state, and browser note in the screenshot inventory. |
| Error state | Admin proof is incomplete. Re-run the route screenshot or browser check, then update the inventory row that names the missing journey, viewport, or demo state. |
| Destructive confirmation | Revoke demo token family: confirm the seeded client, subject, token family, and family-wide irreversibility before capturing destructive-state proof. |

Copy rules:

- Use the locked journey labels exactly: Orient, Configure, Support, Operate.
- Use `DCR onboarding` for partner intake, IATs, self-registered clients, and RAT support. Use `DCR policy` only for issuer registration posture.
- Use `post-logout redirect URIs` for browser destinations and `logout propagation URIs` for RP cleanup endpoints.
- Primary proof actions must use verb plus noun: `Capture admin proof`, `Update screenshot inventory`, `Verify mobile layout`, `Review browser evidence`, `Refresh demo state`, `Document journey model`, `Run design-system contracts`.
- Do not add generic labels such as `Submit`, `OK`, `Cancel`, `Apply`, `Open`, or `Save` without a noun.
- Empty states must say what evidence is absent and name the next proof step.
- Error states must identify the missing route, viewport, journey, or demo state and provide a rerun/update path.
- Screenshot and docs copy must not display or imply recoverability of plaintext secrets after copy-once creation or rotation.

### Destructive And Risky Proof States

| Action | Confirmation Contract |
|--------|-----------------------|
| Revoke consent grant | Name the seeded client, subject/account, scopes if available, and that remembered grant reuse will stop. |
| Revoke token | Name the seeded token type, client, subject/account, expiration, and revocation reason. |
| Revoke token family | Name the seeded token family, client, subject/account, active-token count if available, and family-wide irreversibility. |
| Retry logout delivery | Show seeded endpoint/client/delivery ID and explain that retry re-enqueues delivery without changing logout event truth. |
| Discard logout delivery | Name seeded endpoint/client/delivery ID and explain that delivery will no longer retry. |
| Retire or activate key | Name seeded key ID, use, state, and signing/encryption consequence. |
| Rotate client secret or registration access token | Use copy-once panel wording and exclude plaintext from docs, screenshot inventory, logs, and later screenshots. |
| Revoke initial access token | Name seeded token label/client/policy context if available and explain partner intake consequence. |

## Demo State Contract

Demo seeds must exercise the full operator state matrix without resembling production tenant data:

| State | Required Examples |
|-------|-------------------|
| Healthy | Active first-party client, active token, remembered consent, active key, completed logout delivery |
| Warning | Expiring key, retryable logout delivery, pending interaction, pending device authorization, policy exception pressure |
| Incident | Reuse-detected refresh family, failed logout delivery, revoked consent, disabled client with related tokens |
| Disabled | Disabled client, disabled-risk status badge, unavailable action copy |
| Self-registered | DCR-created client, registration access token context, DCR onboarding route pivots |
| Retryable | Logout delivery with attempt count and next retry timestamp |
| Revoked | Revoked token, revoked token family, revoked consent, revoked IAT |
| Expired | Expired access/refresh token, expired device authorization, expired IAT, expired interaction |
| Long-value | Client ID, endpoint URL, token family ID, logout delivery ID, subject/account ID, key ID, and scopes that wrap on mobile |
| Copy-once | IAT minting, client secret rotation, RAT rotation, and redacted after-created state |

Seed values must be deterministic, obviously artificial, and redaction-safe. Use non-secret placeholders for screenshots; never persist plaintext token, secret, IAT, RAT, user code, verifier, or credential material into docs or inventories.

## Screenshot And Browser Contract

- Capture desktop and mobile screenshots for every approved admin route. Mobile proof target is 390px wide.
- Each screenshot must include enough top-level context to identify journey label, page job, selected route/nav state, and primary route content.
- Long values, badges, filters, rows, actions, and confirmation panels must not overlap or force page-level horizontal scrolling in mobile proof.
- Browser click-through must start from overview, visit each route group, exercise safe read-only navigation, and record any confirmation workflow without executing irreversible production-like actions.
- Screenshot filenames must be deterministic and route-derived, for example `admin-tokens-desktop.png` and `admin-tokens-mobile.png`.
- The inventory must fail deterministic tests when a route lacks desktop screenshot, mobile screenshot, journey label, demo state, or browser note.

## Motion And Interaction Contract

Motion remains CSS-only and must serve feedback, focus/hover affordance, or state continuity.

| Token | Value | Usage |
|-------|-------|-------|
| `--ls-motion-duration-fast` | 150ms | Hover, focus, border, background, and shadow feedback |
| `--ls-motion-duration-medium` | 220ms | Small disclosure or flash continuity only when already present |
| `--ls-motion-ease-standard` | `cubic-bezier(0.4, 0, 0.2, 1)` | Default easing |

Rules:

- Respect `prefers-reduced-motion`; transition and animation duration must reduce to near-zero and active transforms must be neutralized.
- Do not add decorative motion, route-transition choreography, or a broad LiveView JS animation layer.
- Focus states must remain visible on primary nav, secondary nav, filters, row links, buttons, confirmation controls, and copy-once panels during browser proof.
- Disabled actions must explain why they are unavailable or route the operator to the missing prerequisite.

## Documentation Contract

`docs/operator-admin.md` must describe the final admin journey model and remain subordinate to `docs/supported-surface.md`.

Required docs language:

- Lockspire owns the embedded admin operator surface only after the host routes a trusted operator to the mounted admin router.
- The host owns staff sessions, MFA, role checks, tenant policy, layouts, product branding, and product-specific authorization.
- The admin journey model is Orient, Configure, Support, and Operate.
- DCR onboarding, DCR policy, post-logout redirect URIs, and logout propagation URIs use the locked vocabulary from Phase 107.
- Operator docs must point readers to proof artifacts without exposing screenshot seed plaintext secrets.

Documentation must avoid:

- Standalone hosted-auth-service framing.
- Claims that Lockspire owns staff login, staff roles, MFA, tenant policy, or product branding.
- Marketing-style copy that hides safety boundaries.
- Screenshots or snippets containing raw secrets or real-looking credentials.

## Contract Fences

Phase 110 planning should add or extend deterministic proof for:

- Demo seed coverage for healthy, warning, incident, disabled, self-registered, retryable, revoked, expired, long-value, and copy-once states.
- Screenshot inventory coverage for every Phase 107 route and both desktop/mobile viewports.
- Browser click-through evidence that starts from overview and reaches every route group.
- Mobile no-page-overflow proof at 390px for the final route surface.
- `docs/operator-admin.md` journey model and host-owned boundary alignment with `docs/supported-surface.md`.
- No generic CTA labels in newly touched proof/demo/docs surfaces.
- No inline layout styles or arbitrary non-`lockspire-admin-*` admin classes.
- Reduced-motion contract preservation and active-transform neutralization.
- Redaction assertions that secret/token plaintext is absent from list/detail HTML, screenshots, docs, logs, screenshot inventory, and demo proof fixtures.

Primary deterministic fence remains `test/lockspire/web/live/admin/design_system_contract_test.exs`, with focused LiveView/browser/screenshot inventory tests added only where they provide meaningful route-surface proof.
