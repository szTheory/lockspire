<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser proof -> persisted artifacts | Screenshots and notes can leak secrets or overclaim coverage |
| Manual evidence -> phase verification | Manual/browser gaps can be mistaken for passing automated proof |
| Admin confirmation UI -> screenshot workflow | Capturing risky flows must not execute irreversible production-like actions |

## ASVS Level 1 / High-Block Gate

| Gate | Handling |
|------|----------|
| Baseline | OWASP ASVS 5.0.0 Level 1 |
| Block condition | Block on HIGH information-disclosure, false-verification, or host-boundary issues. |
| Applicable categories | V4 Access Control, V5 Input Validation, V6 Cryptography |
| Executor handling | If browser evidence cannot be captured, record `status: gaps`; do not mark verification passed. If a screenshot contains secret material, discard and recapture with redacted/artificial state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-110-11 | Information Disclosure | screenshots and browser evidence | mitigate | inspect captures for secret plaintext and keep screenshot paths evidence-only |
| T-110-12 | Tampering | verification status | mitigate | `110-VERIFICATION.md` may use `status: passed` only after all commands and browser/screenshot proof pass |
| T-110-13 | Repudiation | manual browser proof | mitigate | evidence log records route, viewport, action, outcome, and exact gap reason where proof is missing |
| T-110-14 | Tampering | destructive admin workflows | mitigate | record confirmation screens without confirming irreversible production-like actions |
| T-110-SC | Tampering | package manager installs | accept | no dependency installation or package-manager task is allowed in this plan |
</threat_model>
