<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| startup script -> database | Script creates, migrates, truncates/reseeds demo state, and must fail safely on real DB errors. |
| startup script -> HTTP listener | Script controls when readiness is reported to the maintainer. |
| logs -> operator | Readiness output is visible in terminal and must not expose secrets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-112-05 | Tampering | database setup | mitigate | Tolerate only already-existing database on `ecto.create`; continue to run migrations and the single seed source. |
| T-112-06 | Denial of Service | readiness loop | mitigate | Use bounded Postgres and HTTP wait loops that exit non-zero on timeout. |
| T-112-07 | Information Disclosure | startup logs | mitigate | Print only minimal readiness line; defer accounts, clients, and smoke command to Phase 114 and never print secrets/tokens/cookies. |
| T-112-08 | Repudiation | skipped Docker proof | mitigate | Require summary to record whether runtime Docker proof ran or was skipped. |
| T-112-SC | Tampering | package-manager installs | accept | `mix deps.get` is required for the demo container. Do not add npm/pip/cargo installs or remote installer scripts. |
</threat_model>
