<threat_model>
Security posture: Phase 114 uses an ASVS Level 1 posture with a high threshold for introducing new risk; this plan only emits maintainer-local demo information and must preserve strict redaction.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| maintainer environment -> shell script | `LOCKSPIRE_DEMO_BASE_URL` enters demo tooling and is reflected in startup output. |
| seed fixture truth -> startup logs | Seeded accounts/clients are summarized into terminal logs. |
| Docker startup -> maintainer terminal | Startup logs can be copied into issues or CI logs and must avoid sensitive material. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-114-01 | Information Disclosure | `examples/adoption_demo/bin/docker-info` | mitigate | Use static allowlisted account/client fields and contract tests proving sensitive seed material is absent from source and rendered output. |
| T-114-02 | Spoofing | URL output | mitigate | Derive every public URL from trimmed `LOCKSPIRE_DEMO_BASE_URL`; contract tests exercise a non-default base URL. |
| T-114-03 | Tampering | Startup order | mitigate | Call `docker-info` only after `wait_for_http` so the banner does not claim readiness before public HTTP proof. |
| T-114-04 | Repudiation | Startup proof | accept | Shell output is maintainer-local demo proof, not an audit log; no production accountability claim is added. |
| T-114-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install tasks are planned; package legitimacy audit lists no additions. |
</threat_model>
