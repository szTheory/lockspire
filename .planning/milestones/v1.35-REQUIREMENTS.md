# Requirements: Lockspire v1.35 CI/CD Efficiency And Release Hygiene

**Defined:** 2026-06-30
**Status:** IMPLEMENTED IN WORKTREE
**Core Value:** CI should be fast, deterministic, low-waste, and trustworthy without hiding real release risk.

## v1.35 Requirements

### CI Signal And Runtime

- [x] **CI-01**: Fast checks stop duplicating security work already covered by `mix qa`.
- [x] **CI-02**: PR CI keeps Dialyzer out of the required fast gate until the baseline is clean; maintainers can still run `mix qa.dialyzer` explicitly.
- [x] **CI-03**: Minimum supported Elixir/OTP compatibility has an explicit CI job instead of relying only on latest-version checks.

### Release Hygiene

- [x] **CI-04**: Release workflow and CI jobs use explicit Elixir/OTP versions and precise Mix cache keys.
- [x] **CI-05**: Package hygiene tests catch local artifacts and backup files before Hex packaging.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Full test sharding | Current focused runs are fast; sharding adds complexity before there is evidence of a wall-clock bottleneck. |
| Heavy coverage reporting on every PR | Coverage can become a low-signal runtime tax unless tied to a specific gate. |
| Docker Compose adoption-demo smoke in PR CI | The existing Python black-box smoke is the deterministic CI proof; full Compose remains local maintainer workflow. |
