# Milestone v1.34: Prefix-Isolated Storage

**Status:** IMPLEMENTED IN WORKTREE 2026-06-30
**Focus:** Dedicated PostgreSQL schema support for new installs, with legacy compatibility.

## Overview

v1.34 makes the database boundary match Lockspire's embedded-library promise. New generated installs keep Lockspire-owned tables out of the host app's default public schema, while existing apps stay on their current no-prefix behavior until they explicitly opt in.

## Delivered

- `Lockspire.Config.storage_prefix/0` and `Lockspire.Config.oban_prefix/0`.
- `Lockspire.Storage.Ecto.Prefix` for normalization, Ecto opts, Oban opts, and SQL identifier quoting.
- `Lockspire.Storage.Ecto.Migration` helpers for schema creation, prefixed tables, indexes, references, and qualified raw SQL table names.
- All shipped migrations moved to the prefix-aware migration helpers.
- Repository helpers pass prefix options through Ecto calls without dropping existing `log: false` safeguards.
- Workers, logout propagation, registration management, and front-channel logout queries use prefix-aware repo options.
- Generated install config defaults to `storage_prefix: "lockspire"` and `oban_prefix: "lockspire"`.
- Upgrade/install CLI accepts explicit `--storage-prefix` and `--oban-prefix`, including `public`.
- Docs and adoption demo updated for the dedicated-schema default.

## Open Follow-Up

- A future migration guide/tool can help existing public-schema users move data into `lockspire`, but it should not be automatic.
- Full operational docs should eventually show backup/restore and psql inspection examples for prefixed installs.
