# Phase 123 - UI Design Contract

> Visual and interaction contract for Phase 123: Operate Queue Flow Polish. Generated by gsd-ui-researcher for planner, executor, checker, and auditor use.

Phase 123 polishes only the existing Operate queues: `/admin/interactions`, `/admin/device_authorizations`, and `/admin/logouts`. These pages remain read-only support-review surfaces for observing and correlating queue state. This phase must not add queue mutation controls, public routes, public lab/browser-proof routes, storage schema changes, protocol behavior, public theming, host customization seams, or new support-surface claims.

Sources: `AGENTS.md`, `.planning/STATE.md`, `.planning/ROADMAP.md`, `.planning/REQUIREMENTS.md`, `123-CONTEXT.md`, `123-RESEARCH.md`, `121-ROUTE-SCORECARDS.md`, `122-UI-SPEC.md`, `brandbook/`, `lib/lockspire/web/admin_css.ex`, `lib/lockspire/web/components/admin_components.ex`, and current Operate LiveViews/tests.

## Design System

| Property | Value |
|----------|-------|
| Tool | none; Phoenix function components plus embedded `lockspire-admin-*` CSS |
| Preset | not applicable |
| Component library | Lockspire-owned `Lockspire.Web.Components.AdminComponents` and existing LiveView/AdminLayout surfaces |
| Icon library | none; use visible text labels for queue status, support notes, and any safe route pivots |
| Font | `--ls-font-display` Familjen Grotesk stack for headings; `--ls-font-sans` Inter stack for UI/body; `--ls-font-mono` JetBrains Mono stack for IDs, handles, timestamps, endpoint URLs, and redacted values |
| CSS architecture | BEM/design-token `lockspire-admin-*`; no Tailwind, shadcn, public theming engine, host registry, data-grid package, or arbitrary one-off classes |

Implementation boundary:

- Use existing Operate routes only: `/admin/interactions`, `/admin/device_authorizations`, and `/admin/logouts`.
- Use existing primitives by default: `page_hero`, `pane`, `metric_grid`, `summary_stat`, `resource_list`, `dense_resource_row`, `status_badge`, `long_value`, and `empty_state`.
- Use logout deliveries as the reference scan pattern, then align interactions and device authorizations where the same pressure-first anatomy improves scanability.
- Do not create `operate_queue_row` or `operate_queue_page` by default. A small internal component is allowed only if duplication across all three queues becomes error-prone and route-specific domain language remains explicit through attrs/slots.
- Do not convert the queues to responsive tables, data grids, column comparison tools, bulk selection, sorting, or operator preference controls.
- Do not add `handle_event/3`, `phx-click`, `phx-submit`, retry, discard, approve, deny, logout-now, requeue, pause/resume, or worker-control affordances in these pages.

## Operate Route Contract

| Route | Primary Job | Primary Decision | Primary Page Label | Required Follow-Up |
|-------|-------------|------------------|--------------------|--------------------|
| `/admin/interactions` | Inspect active authorization interaction queue state. | Which pending login or consent interaction is waiting, risky, denied, expired, or complete? | `Review interactions` | Preserve overview/support orientation; no detail route or mutation route is introduced. |
| `/admin/device_authorizations` | Inspect device authorization queue and expiry state. | Which device-flow requests are pending, approved-but-waiting, denied, expired, or consumed? | `Review device authorizations` | Preserve overview/support orientation; no raw code exposure or command route is introduced. |
| `/admin/logouts` | Inspect logout propagation delivery outcomes and support pressure. | Which logout deliveries are waiting, retrying, retryable, discarded, skipped, rendered, or completed? | `Review logout deliveries` | Optional safe configuration pivot may point to existing logout-propagation client workflow only when it reads as a route pivot, not as a worker command. |

Every Operate page must answer, in this order:

1. Which Operate queue am I reviewing?
2. What status pressure exists right now?
3. Which client, subject/account, channel/prompt, endpoint, or durable non-secret handle explains the row?
4. What age, expiry, last activity, poll, attempts, or support note changes the support interpretation?
5. What safe support/configuration pivot exists, if any, without implying Lockspire can act from this page?

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs / `--ls-space-1` | 4px | Badge internals, tiny inline gaps, destructive-group offset already shipped |
| sm / `--ls-space-2` | 8px | Dense row title/subtitle gaps, status clusters, compact metadata relationships |
| md / `--ls-space-4` | 16px | Default pane, metric, dense row, resource list, and page content spacing |
| lg / `--ls-space-6` | 24px | Pane padding, page section padding, route group spacing |
| xl / `--ls-space-8` | 32px | Admin body padding and large page gaps |
| 2xl / `--ls-space-12` | 48px | Empty-state vertical padding and major route breaks |
| 3xl | 64px | Reserved page-level spacing only; do not introduce a new token unless proof shows a true page-level gap is needed |

Exceptions:

- Existing shipped compatibility values at 12px, 20px, and 40px may remain. Do not introduce new spacing values for Phase 123 polish.
- Standard controls keep `--ls-control-height: 40px` minimum if an existing safe route pivot or theme control appears in a touched area.
- Below 720px, dense rows, pane headers, status clusters, support notes, and any safe route pivots stack vertically and preserve a minimum 16px relationship between row content groups.

| Heading | 16px (`--ls-type-heading-size`) | 600 | 1.25 |

Rules:

- New Phase 123 UI copy uses exactly these four sizes and exactly two weights: 400 and 600.

- Use mono only for durable handles, delivery IDs, redacted authorization handles, endpoint URLs, timestamps, and code-like status values.
- Long mono values must render through `long_value` or an existing class with `overflow-wrap: anywhere`.
- Page headings and pane headings use operator language, not backend table names.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ls-surface-page`: light `#f8fafc`, dark `#0b1220` | Admin shell background and broad quiet page surface |
| Secondary (30%) | `--ls-surface-panel`: light `#ffffff`, dark `#131c2e`; plus `--ls-surface-muted` | Page heroes, panes, metric cards, dense rows, support-note panels, and empty states |
| Accent (10%) | `--ls-text-accent`: light Deep Cyan `#0e7490`, dark Signal Cyan `#22d3ee` | Operate eyebrow, active/current navigation, focus rings, and safe existing-route links only |
| Danger / destructive semantic | `--ls-status-danger-*`: light text `#991b1b` / bg `#fee2e2`; dark text `#fca5a5` / bg `#2e1517` | Incident, discarded, security-sensitive, and error states; no destructive action controls are approved in Phase 123 |

Accent reserved for: `Operate` eyebrow, active/current navigation, safe existing-route links when used, selected support context emphasis, and focus-visible rings. Accent must not be used for decorative panels, every badge, all metadata labels, every link indiscriminately, or normal body text.

Status semantics:

| Status Group | Contract |
|--------------|----------|
| Waiting | Pending login, pending consent, pending device authorization, enqueued logout delivery, attempted delivery under observation. |
| Warning | Retryable logout delivery, denied interaction/device state when operator attention may be required. |
| Danger | Discarded logout delivery, reuse/security-sensitive terminal state, or true error state. |
| Disabled / closed | Expired interaction or device authorization; unavailable or closed state where no page action exists. |
| Completed | Completed interaction, consumed device authorization, succeeded/rendered/skipped logout delivery when it is historical support truth. |
| Provenance / info | Channel, origin, grant kind, or explanatory support context that is not a health signal. |

Color is never the only state signal. Badges must include visible text, rows must carry pressure/support copy, and errors must describe the next support-safe path.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | No command CTA is approved. Primary read-only page labels are `Review interactions`, `Review device authorizations`, and `Review logout deliveries`. |
| Empty state heading | Interactions: `No authorization interactions waiting for review`; device authorizations: `No device authorizations waiting for review`; logouts: `No logout deliveries waiting for review`. |
| Empty state body | Interactions: `There are no authorization interaction records waiting for operator review.` Device authorizations: `There are no device authorization records waiting for operator review.` Logouts: `There are no logout propagation records waiting for operator review.` |
| Error state | `Operate queue context could not be loaded. Reload this Operate workflow or return to overview; no queue action was taken from this page.` |
| Destructive confirmation | none; retry, discard, approve, deny, logout-now, requeue, pause/resume, and worker controls are not in scope. |

Copy rules:

- Use the journey label `Operate` exactly.
- Use Lockspire domain nouns: operator, account, client, interaction, device authorization, logout delivery, endpoint, status, expiry, attempts, support note.
- Preferred state phrases include `Waiting for login`, `Waiting for consent`, `Expired before completion`, `Approved, waiting`, `Retryable delivery failure`, `Terminal queue outcome`, `Delivery work completed`, and `Read-only support truth`.
- Status words such as `Retrying`, `Discarded`, `Approved`, and `Denied` are allowed as state labels and badge text. They must not appear as active command labels.
- Avoid generic labels such as `Submit`, `Apply`, `OK`, `Open`, `Go`, `Continue`, `Manage`, or one-word command copy.
- Avoid backend-leaking terms in visible UI: SQL row, Oban job, worker internals, raw hash, database failure, code material, request object, raw response, raw params.

## Page Composition Contract

### Shared Operate Spine

- Lead with `page_hero` using eyebrow `Operate`, route-specific title, and one-sentence queue purpose.
- Follow with one `pane` per queue using the route-specific `Review ...` title and read-only support-review subtitle.
- Place `metric_grid` before rows. Metrics must represent status buckets, not command queues.
- Render rows with `resource_list` and `dense_resource_row`; do not use `<table>`, `responsive_table`, a data grid, or fixed-width columns for these pages.
- Use the row `status` slot for `status_badge`; status text must remain visible in all themes.
- Use the row `meta` slot for durable non-secret metadata. Put support notes in `lockspire-admin-dense-resource-row__note` or equivalent full-width note treatment.
- Do not use the row `actions` slot unless the item is an existing safe route pivot and cannot be mistaken for a queue command.

### `/admin/interactions`

- Hero title: `Authorization interaction queue`.
- Pane title: `Review interactions`.
- Metrics: `Pending login`, `Pending consent`, `Completed`, `Denied`, `Expired`.
- Row title should remain route-specific: `Authorization interaction` or a clearer pressure title such as `Waiting for login interaction`.
- Row subtitle must communicate status pressure, not repeat `Review interactions`.
- Required safe fields: interaction id, redacted client handle, redacted account/subject handle, prompt, created/age context, expiry, and status.
- Forbidden fields: authorization codes, request object internals, cookies, session tokens, nonce/state values, PKCE material, raw params, raw sensitive return values.

### `/admin/device_authorizations`

- Hero title: `Device authorization queue`.
- Pane title: `Review device authorizations`.
- Metrics: `Pending`, `Approved`, `Denied`, `Expired`, `Completed`.
- Row title should remain route-specific: `Device authorization` or a clearer pressure title such as `Pending device authorization`.
- Row subtitle must communicate device-flow pressure, expiry pressure, poll context, or completed/terminal state.
- Required safe fields: redacted client handle, redacted subject/account handle, redacted durable authorization handle, status, expiry, poll interval/next poll or available lifecycle activity.
- Device activity copy must use available domain fields: `effective_poll_interval_seconds`, `next_poll_allowed_at`, `approved_at`, `denied_at`, `consumed_at`, `expired_at`, and `expires_at`. Do not reach for `auth.updated_at` unless a narrow internal read-model change is explicitly planned.
- Forbidden fields: raw `device_code`, raw `user_code`, hashes, raw `verification_handle`, authorization codes, token material, PKCE material, state, nonce, raw params, backend storage details.

### `/admin/logouts`

- Hero title: `Logout propagation queue`.
- Pane title: `Review logout deliveries`.
- Metrics: `Waiting`, `Retrying`, `Failed`, `Discarded`, `Completed`.
- Row title should include channel: `Back-channel logout delivery`, `Front-channel logout delivery`, or `Unknown channel logout delivery`.
- Row subtitle must communicate delivery pressure using the existing `delivery_pressure/1` pattern.
- Required safe fields: delivery id, redacted client handle, channel, endpoint URL, attempts, status pressure, last activity, and support note.
- Optional safe fields: HTTP status or concise failure class, only when it makes retryable/incident state clearer and does not expose raw response content.
- Forbidden fields: logout token JTI as an operator-facing handle, Oban job ID as the support concept, raw response bodies, cookies, endpoint secrets, live tenant hostnames, SQL rows, worker internals, and session data.

## Interaction Contract

| Interaction | Required Behavior |
|-------------|-------------------|
| Queue review | Read-only scanning only. Rows expose state and support context; they do not mutate queue records. |
| Safe route pivot | Allowed only to an existing route when the link is support/configuration context, not a command. It must have visible text, href, focus-visible ring, and no `phx-click`. |
| Status badges | Use `status_badge` with visible text and existing domain metadata. Add central status metadata only if a changed state would otherwise render misleading fallback copy. |
| Long values | Use `long_value` with `kind: :id`, `:url`, `:timestamp`, or `:text`. Never manually truncate sensitive-looking strings. |
| Motion | Existing hover/focus transitions may remain. Do not add auto-refresh animation, motion-only expiry feedback, parallax, bounce, or progress animation. Reduced motion must neutralize nonessential transitions through current CSS. |
| Keyboard focus | Focus rings remain visible on nav links, theme controls, and any safe route links. Dense rows without links do not need fake focus affordances. |

Unsupported controls are explicitly banned: `Retry`, `Retry now`, `Discard`, `Approve`, `Deny`, `Logout now`, `Requeue`, `Worker control`, `Pause`, and `Resume`.

## State Coverage Contract

| State | Required UI Treatment |
|-------|-----------------------|
| Empty true-zero | Route-specific empty heading and body from the copy contract; no command controls. |
| Dense results | Metrics first, then dense rows. Keep title/status/pressure visible before secondary metadata. |
| Incident | Warning or danger badge plus support note that names the observation path without exposing internals. |
| Expired | Disabled/closed status with copy that explains completion did not happen before expiry. |
| Retryable logout | Warning status plus endpoint/attempt/last activity/support note; no retry button. |
| Discarded logout | Danger or terminal status plus historical support-truth copy; no discard button. |
| Skipped logout | Completed/terminal support truth, not an error if the domain marks it as best-effort skipped. |
| Rendered logout | Completed front-channel support truth; preserve endpoint/timestamp context. |
| Completed/succeeded | Completed status plus durable row context; do not hide completed rows if included by the current list scope. |
| Long identifiers and URLs | `long_value` wrapping with no page-level horizontal overflow at 320px, 390px, 768px, 1024px, or 1440px. |
| Queue load failure | Error copy says observation failed and no action was taken; do not expose repository, SQL, Oban, or stack details. |

## Responsive And Accessibility Contract

- At 320px, 390px, 768px, 1024px, and 1440px, touched Operate pages must not require page-level horizontal scrolling.
- Below 720px, dense rows stack in this order: title and pressure subtitle, status cluster, support context, long values, secondary metadata, optional safe route pivot.
- Status meaning never relies on color alone; badge text and pressure/support copy are required.
- Focus rings use the existing `--ls-focus-ring-*` tokens and must not be removed.
- `aria-describedby`, `aria-labelledby`, and `aria-controls` targets must resolve when introduced.
- Page and row copy must remain legible in light, dark, and system theme modes through semantic `--ls-*` aliases.
- Reduced motion keeps orientation and focus feedback but neutralizes active transforms and nonessential transitions.
- No icon-only actions, tooltip-only explanations, hover-only disclosures, or hidden support notes are approved.

## Security And Redaction Contract

- Render only allowed non-secret queue data named in this UI-SPEC and `123-CONTEXT.md`.
- Continue using `Lockspire.Redaction.handle/2` for client, account/subject, device authorization, and other durable handles unless an existing safer helper is already in use.
- Continue using `AdminComponents.long_value` for durable IDs, endpoint URLs, timestamps, and redacted handles.
- Never render access token plaintext, refresh token plaintext, authorization codes, client secrets, cookies, session tokens, PKCE verifier/challenge material, state, nonce, raw device code, raw user code, hashes, raw verification handle, logout token JTI, raw request objects, raw params, raw response bodies, Oban IDs, SQL internals, or worker internals.
- Demo/test/browser evidence must use redaction-safe fixtures. Long URLs and IDs should stress wrapping without resembling real production tenants, secrets, or tokens.
- Do not create copy-to-clipboard, reveal, decode, inspect hash, export, bulk action, retry/discard, approve/deny, or raw audit dump controls.
