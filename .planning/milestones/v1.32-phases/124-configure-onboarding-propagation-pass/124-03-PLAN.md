| Boundary | Description |

| LiveView action form -> key lifecycle handlers | Operator lifecycle intent crosses into existing publish/activate/retire behavior. |
| key storage -> operator UI | UI may render public key metadata but must never expose private material. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-124-09 | Information Disclosure | `keys_live/index.ex`, `keys_live/show.ex`, `keys_live/action_component.ex` | mitigate | Render public metadata only; tests deny private JWK/private key/export/raw internals. |
| T-124-10 | Tampering | key publish/activate/retire controls | mitigate | Confirmation panels require explicit checkbox confirmation and concrete consequence copy before lifecycle changes. |
| T-124-11 | Repudiation | lifecycle notices | mitigate | Notices distinguish changed, already-current, and failed states without backend leakage. |
| T-124-12 | Elevation of Privilege | Admin route/API boundary | mitigate | Keep existing key routes and handlers; no force-publish, remote fetch, new Admin APIs, schemas, migrations, or packages. |
| T-124-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager install tasks are planned; executor must not add package dependencies or registry artifacts. |
