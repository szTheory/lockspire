## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator browser -> LiveView URL params | Account/client/status filters enter LiveViews through query parameters and form controls. |
| LiveView -> Admin API | Index LiveViews read token and consent data through existing `Lockspire.Admin` delegations. |
| Admin data -> rendered HTML | Token, consent, account, client, family, scope, and timestamp values become operator-visible HTML. |
| Source/test repo -> package surface | Admin UI source changes must not create public component, route, schema, or package commitments. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-122-01 | Information Disclosure | Token/consent index rendered HTML | mitigate | Render only redacted handles, status text, token/grant type, scopes, and timestamps through `long_value`; tests deny token hashes, secrets, verifier, auth-code, user-code, and plaintext token terms. |
| T-122-02 | Elevation of Privilege | Index actions | mitigate | Index pages expose only filter and review navigation actions backed by existing routes; no revoke, bulk, reveal, export, debug, protocol, storage, or host-policy controls. |
| T-122-03 | Denial of Service | Dense rows at narrow widths | mitigate | Use existing `dense_resource_row`, `long_value`, mobile stacking, and design-system source contracts to avoid page-level overflow from long handles/scopes. |
| T-122-04 | Tampering | LiveView data access | mitigate | Keep reads in `Admin.list_tokens/1` and `Admin.list_consents/1`; no raw Ecto/Repository calls in LiveViews and no schema/migration files. |
| T-122-SC | Tampering | npm/pip/cargo/mix installs | accept | No package-manager install is planned; `mix.exs`, `mix.lock`, package metadata, and browser tooling are outside `files_modified`. |
</threat_model>
