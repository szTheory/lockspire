## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator browser -> LiveView event | Confirmation checkbox input crosses into `handle_event/3`. |
| LiveView -> Admin consent API | Detail reads and revocation call existing consent Admin delegations. |
| Consent Admin data -> rendered HTML | Grant status, scopes, client/account pivots, timestamps, and revocation data become support-visible evidence. |
| Revocation result -> operator copy | Backend success/failure/closed states are summarized for operator action. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-122-10 | Tampering | Consent revoke form | mitigate | Require explicit checkbox confirmation, keep existing Admin API mutation call, and disable closed already-revoked action in the UI. |
| T-122-11 | Repudiation | Consent revocation failure copy | mitigate | Use locked non-final copy stating revocation could not be confirmed and the consent grant may still be active. |
| T-122-12 | Information Disclosure | Consent detail rendered HTML | mitigate | Preserve redacted handles and deny consent hash, secret, token, verifier, user-code, and raw sensitive account leakage in tests. |
| T-122-13 | Elevation of Privilege | Consent detail action surface | mitigate | Expose only revoke consent action backed by existing Admin API; no host account, session, token, worker, reveal/export/debug, bulk, or protocol controls. |
| T-122-14 | Denial of Service | Consent detail long scopes | mitigate | Use existing `long_value` and wrapping primitives for scope lists and pivots. |
| T-122-SC | Tampering | npm/pip/cargo/mix installs | accept | No dependency or package-manager install is planned; `mix.exs`, `mix.lock`, package metadata, and browser tooling are outside `files_modified`. |
