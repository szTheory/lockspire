<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator browser -> LiveView event | Confirmation checkbox input crosses into `handle_event/3`. |
| LiveView -> Admin token API | Detail reads and revocations call existing token Admin delegations. |
| Token Admin data -> rendered HTML | Token family lineage, status, timestamps, scopes, and counts become support-visible evidence. |
| Revocation result -> operator copy | Backend success/failure/closed states are summarized for operator action. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-122-05 | Tampering | Token revoke/family revoke forms | mitigate | Require explicit checkbox confirmation, keep existing Admin API mutation calls, and disable closed/no-family actions in the UI. |
| T-122-06 | Repudiation | Token revocation failure copy | mitigate | Use locked non-final copy stating revocation could not be confirmed and the token may still be active. |
| T-122-07 | Information Disclosure | Token detail rendered HTML | mitigate | Preserve redacted handles and deny plaintext token/hash/family/account leakage in tests. |
| T-122-08 | Elevation of Privilege | Token detail action surface | mitigate | Expose only single-token and family revocation actions already backed by Admin APIs; no host logout, account suspension, consent revocation, worker controls, reveal/export/debug controls, or new capabilities. |
| T-122-09 | Denial of Service | Token detail long lineage | mitigate | Use existing `dense_resource_row`, `long_value`, and `timestamp` primitives for lineage rows and long metadata. |
| T-122-SC | Tampering | npm/pip/cargo/mix installs | accept | No dependency or package-manager install is planned; `mix.exs`, `mix.lock`, package metadata, and browser tooling are outside `files_modified`. |
</threat_model>
