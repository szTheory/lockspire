### Follow-Up Finding Closed

**Alternate Compose project reprint command is not fully project-aware**

Affected requirements: `CONFLICT-01`, `INFO-04`, partial `DOCS-02`.

Phase 113 allows alternate project names via `COMPOSE_PROJECT_NAME` or `--project-name`, and lifecycle helpers accept `--project`. Phase 114's `docker-info` banner prints:

```sh
docker compose -f examples/adoption_demo/docker-compose.yml exec web ./bin/docker-info
```

That worked for the default project and when the maintainer preserved `COMPOSE_PROJECT_NAME`, but it was incomplete for a demo started with `docker compose --project-name lockspire-adoption-demo-alt ...`.

Evidence:

- `examples/adoption_demo/bin/docker-info` prints the default reprint command.
- `docs/adoption-demo.md` documents alternate project startup.
- `test/lockspire/adoption_demo_docker_contract_test.exs` pins the default reprint command only.

Closure:

- `examples/adoption_demo/bin/docker-info` now prints the default reprint command and a `COMPOSE_PROJECT_NAME=lockspire-adoption-demo-alt ... exec web ./bin/docker-info` project-aware form.
- `docs/adoption-demo.md` now documents project-aware reprint guidance in startup-output and readiness troubleshooting sections.
- `test/lockspire/adoption_demo_docker_contract_test.exs` now asserts the project-aware reprint command in both banner and docs contracts.
