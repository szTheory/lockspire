# Requirements: Lockspire v1.34 Prefix-Isolated Storage

**Defined:** 2026-06-30
**Status:** IMPLEMENTED IN WORKTREE
**Core Value:** Lockspire behaves like a respectful guest inside a host Phoenix app database.

## v1.34 Requirements

### Storage Prefix Defaults

- [x] **PREFIX-01**: New generated installs default Lockspire and Oban tables into a dedicated PostgreSQL schema named `lockspire`.
- [x] **PREFIX-02**: Existing installs remain backward-compatible when no prefix config is present; no silent data move happens.
- [x] **PREFIX-03**: Hosts can explicitly choose `public` for Lockspire and Oban tables through install/upgrade options and generated config.

### Migration And Runtime Prefixing

- [x] **PREFIX-04**: Lockspire migrations create the configured schema and apply prefix to tables, indexes, unique indexes, references, and raw SQL migration paths.
- [x] **PREFIX-05**: Oban migrations and Oban runtime config respect `oban_prefix`, defaulting to `storage_prefix`.
- [x] **PREFIX-06**: Ecto repository reads/writes, direct worker/controller queries, and Oban job inserts pass prefix options consistently.

### Docs And Example App

- [x] **PREFIX-07**: Install, SaaS recipe, supported-surface, upgrade, and example app docs explain the dedicated-schema default, explicit-public opt-in, and no-silent-migration rule.
- [x] **PREFIX-08**: Adoption-demo config and seed cleanup use the new prefix-aware table qualification path.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Automatic public-to-lockspire data migration | Too risky for OSS host apps; should be an explicit future guide/tool if needed. |
| Arbitrary search_path management | Ecto prefix options are more explicit and safer for an embedded library. |
| Multi-tenant per-request prefix support | Lockspire issuer storage is global provider state in v1; tenant policy belongs to host seams. |
