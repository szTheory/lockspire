# Requirements: Lockspire v1.33 OSS Adoption Trust

**Defined:** 2026-06-30
**Status:** IMPLEMENTED IN WORKTREE
**Core Value:** A Phoenix team can become a trustworthy OAuth/OIDC provider inside its existing app without inventing the dangerous parts itself.

## v1.33 Requirements

### Public Surface And Adoption Trust

- [x] **TRUST-01**: Public OAuth/OIDC routes and operator admin routes are separated so host apps must explicitly mount and guard `Lockspire.Web.AdminRouter`.
- [x] **TRUST-02**: The install verifier fails with actionable guidance when the host app omits the admin mount, public mount, or host-owned device verification routes.
- [x] **TRUST-03**: Generated install docs and examples explain the narrow host seam: host-owned login, account resolution, consent handoff, admin guard, and layouts remain outside Lockspire.

### Package And Release Trust

- [x] **TRUST-04**: Hex package inputs exclude local build artifacts and backup files while keeping migrations, templates, docs, README, changelog, license, and source.
- [x] **TRUST-05**: Adoption-demo docs keep the demo as repo-local adopter proof, not production Docker packaging, hosted auth, or broader public support surface.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Hosted auth service | Violates embedded-library boundary. |
| Host staff authentication | Host app owns operator authentication and authorization. |
| Full README rewrite | The targeted adoption trust gaps were router boundary, verifier truth, package hygiene, and storage guidance. |
