<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| verified validator output → protected publish job | A validated SHA becomes the code receiving the Hex secret. |
| protected publish job → public GitHub/Hex registries | Privileged publication creates durable public artifacts. |
| public registries → clean-room verifier | Untrusted network artifacts are consumed without publication credentials. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-126-05 | Tampering | publish checkout | critical | mitigate | Checkout and detach only the validator's exact SHA; compare tag target before accepting an existing release. |
| T-126-06 | Information disclosure | post-publish verification | high | mitigate | Keep install truth outside `hex-publish`, with read-only permissions and no `HEX_API_KEY`. |
| T-126-07 | Repudiation | public artifact chain | medium | mitigate | Record SHA, CI run, tag, version, publish result, and uploaded install log in one workflow. |
| T-126-08 | Denial of service | registry propagation waits | medium | mitigate | Use bounded retries and job timeouts; preserve failure logs as artifacts. |
| T-126-SC | Tampering | npm package installs | high | mitigate | No npm package change occurs in this plan; the upload action is pinned to a reviewed full commit SHA. |
</threat_model>
