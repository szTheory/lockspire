<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workflow-run payload → privileged dispatch | Repository event data selects whether publication may begin. |
| workflow-dispatch inputs → shell/git | Maintainer- or automation-supplied strings cross into validation commands. |
| GitHub REST response → verified checkout output | API metadata becomes authorization evidence for the publish job. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-126-01 | Spoofing | CI run evidence | critical | mitigate | Compare workflow identity, repository, event, branch, conclusion, current main SHA, and run head SHA before emitting `verified_sha`. |
| T-126-02 | Tampering | dispatch ref and reason | high | mitigate | Require a full SHA, use env-backed quoted variables, and never pass raw input to checkout. |
| T-126-03 | Repudiation | automated release dispatch | medium | mitigate | Carry the exact CI run ID, release PR number, reason, and SHA into workflow evidence. |
| T-126-04 | Elevation of privilege | pre-merge CI authorizes post-merge code | critical | mitigate | Split merge and dispatch across distinct workflow runs; only the merge commit's successful CI run can dispatch. |
| T-126-SC | Tampering | npm package installs | high | mitigate | No package install occurs in this plan; Phase 126 research audits existing runtime packages before Plan 03. |
</threat_model>
