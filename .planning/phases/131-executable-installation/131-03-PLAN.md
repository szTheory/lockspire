<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser route parameter → consent context | Untrusted interaction identifiers select sensitive authorization state. |
| Host account resolver → Lockspire interaction | Resolved subject must match the stored interaction before a decision is offered. |
| Consent context → generated HEEx | Protocol state is reduced to redaction-safe render facts and a supported completion path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-131-09 | Spoofing | consent subject binding | high | mitigate | Preserve host resolver/Claims resolution and exact stored-subject comparison before returning actionable context. |
| T-131-10 | Tampering | expired/reused interaction | high | mitigate | Reuse the existing expiry, resume, remembered-consent, and finalization state transitions; terminal states expose no controls. |
| T-131-11 | Information disclosure | generated consent UI | high | mitigate | Return/render only allowlisted facts and stable error copy; tests seed sensitive values and assert they do not appear. |
| T-131-12 | Denial of service | duplicate form submission | medium | mitigate | Disable both decisions on submit and preserve normal Phoenix form/CSRF behavior. |
| T-131-13 | Repudiation | completion handling | medium | mitigate | Keep decisions on the existing audited InteractionController endpoint rather than duplicating transitions in generated code. |
