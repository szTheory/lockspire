<objective>
Close ADOPT-D01, ADOPT-D02, and ADOPT-D03: the generated router helper defines
`lockspire_routes/0` as a function returning a heredoc String. A top-level call to it in a host
router evaluates the expression and discards it, so the guide's first documented reading of §3
compiles cleanly and injects **zero** routes. The other documented reading — pasting the body —
fails to compile, because the pasted body names a pipeline no stock host defines and forwards
through a scope with no pipeline at all.

Purpose: both documented readings must work. The macro form satisfies the first; a self-contained,
paste-safe emitted body satisfies the second. This is also the security-relevant half of the
router work: the pipeline the walk currently stands in for is an **empty** one, which would leave
`Lockspire.Web.AdminRouter` reachable by anyone, and the pipeline-less forward would serve the
consent LiveView with no CSRF protection.

Output: a `defmacro` returning a `quote` block that emits its own deny-closed operator pipeline
and halt plug, an explicit browser-piped scope carrying the interaction routes and a
`live_session`-wrapped consent route ahead of the forward, the admin forward ordered before the
public forward, the duplicated admin scope removed — plus a compile fence that reads the real
route table back rather than pattern-matching source text, and the regenerated runtime fixture.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted browser → host router | every route the macro injects is reachable from the public internet unless a pipeline says otherwise |
| host router → Lockspire admin surfaces | the admin forward exposes operator LiveViews that manage clients, consents, tokens, and keys |
| generated file → adopter repository | the emitted body is read, pasted, and edited by adopters; whatever default it carries becomes the default in production hosts |

Deny-closed by construction: an adopter who wires nothing gets a closed door, not an open one. The walk's current stand-in is an empty pipeline, which would leave the admin LiveViews reachable by anyone |
