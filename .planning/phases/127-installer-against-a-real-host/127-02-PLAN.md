<objective>
Close ADOPT-D15: a stock `mix phx.new --database postgres` host locks `ecto_sql 3.14.0`, and
Lockspire's `{:ecto_sql, "~> 3.13.5"}` makes the very first `mix deps.get` after adding the
dependency fail outright — step 1 of the documented adopter path.

Purpose: this is the earliest possible break on the adopter path and it stops the walk before
the installer is ever run. The `.5` was never a deliberate choice: `git log -S'ecto_sql' -- mix.exs`
returns a single commit (the initial skeleton) and the string has been byte-identical since.

Output: an explicit `ecto_sql` range with an inline rationale comment matching the house style
three lines above it, a committed `mix.lock` that actually resolves 3.14.0, a green `mix ci` run
against that resolution, and an `AGENTS.md` stack line that no longer states a pin the build does
not enforce.
</objective>

  <action>
Widening the requirement does not by itself move the lock — `mix deps.get` never re-resolves an
already-locked transitive dependency just because a new constraint permits a newer one. Run
`mix deps.update ecto ecto_sql` explicitly. Both must move together: `ecto_sql 3.14.0` requires
`ecto ~> 3.14.0`, so the real change is `ecto 3.13.6` to `3.14.0` as well as the `ecto_sql` bump.
`decimal` and `db_connection` requirements are already satisfied by the committed lock, so expect
no other entries to move; if any other dependency changes, stop and report it rather than
committing a wider bump than intended.

Commit the resulting `mix.lock`. The lock is the artifact that proves the range resolves; without
it the change is untested and D-23's "land it together with one CI run that actually resolves 3.14"
is unmet.

Before running the suite, grep `lib/lockspire` for `Repo` calls passing query-like keyword options
(`where:`, `select:`, `order_by:`, `preload:`, `limit:`) directly to `Repo` functions such as
`all`, `one`, `get`, `get_by`, `update_all`, `delete_all`. Ecto 3.14.0 turns that previously
ignored mistake into a raise, and it is the single entry in the changelog with real behavior-change
potential for this codebase. Report any hit rather than silently fixing it.

Then run the full `mix ci` lane — it covers `qa`, `docs.verify`, `deps.audit`, `package.build`,
`test.fast`, `test.integration`, and `test.phase3`. A green `mix ci` against the new resolution is
what discharges the unverified half of D-23; changelog analysis alone is not sufficient evidence.
