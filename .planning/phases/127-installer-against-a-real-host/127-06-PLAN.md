<objective>
Close ADOPT-D04, ADOPT-D09, and ADOPT-D16 — the three template defects that make a stock install
either fail to compile or fail to boot.

Purpose: the config template's placeholder issuer is not merely vague, it *raises* — a bare
`https://example.com` cannot satisfy the mount-path consistency rule in
`lib/lockspire/security/policy.ex:104-106`. The same template omits the scope vocabulary, so a
stock install rejects every scope except `openid`; omits the signing algorithm; and omits
`secret_key_base`, which the library cannot infer because it only scans its own app env. Separately
the authorized-apps HEEx nests an EEx tag inside a HEEx attribute expression, which the resolved
LiveView tokenizer rejects outright — the generated host fails to compile immediately after
install, before any wiring is exercised. And the generated resolver sends the browser to a login
route no `phx.gen.auth --live` host has.

Output: a config template that boots, a resolver login path that resolves, a HEEx template that
compiles, and a compile fence over **every** generated `.heex` so this class of defect cannot
reach an adopter again with no host involved at all.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shipped template → adopter repository | `priv/templates/**` ships to every adopter through Hex; a literal committed here reaches every install |
| generated config → Lockspire runtime | the emitted config is the runtime contract for issuer identity, accepted scopes, signing, and the secret used for token and nonce protection |
| untrusted browser → generated authorized-apps page | the rendered list item interpolates a grant identifier into an element attribute |
