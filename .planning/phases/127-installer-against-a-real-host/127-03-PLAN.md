<objective>
Close ADOPT-D08: the documented `mix lockspire.client.create` task exits 1 against a stock
generated host with a runtime error saying the configured repo was never started. It is one of
only two commands the guide's §6 proof bar needs, and it never reaches a database.

Purpose: the task declares `@requirements ["app.config"]`, which loads configuration but never
starts the supervision tree. `mix lockspire.verify` declares exactly the same requirement and
works — because it wraps its repo work in `Ecto.Migrator.with_repo/2`. The fix is to reuse that
in-repo pattern, not to escalate the task to `app.start`, which would boot the host's full
endpoint from a CLI invocation and change what running the command does to a live system.

Output: `Clients.register_client/1` wrapped in `Ecto.Migrator.with_repo/2` exactly as
`lib/lockspire/install/verify.ex:202-217` already does, plus an integration test that proves the
task reaches a repo without `app.start`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI → client registry | switches supplied on the command line become a persisted OAuth client's redirect URIs, scopes, and grant types |
| Mix task → host runtime | the task starts the configured repo inside an otherwise unstarted application |
| task stdout → operator terminal | a generated client secret is printed once and never recoverable afterwards |
