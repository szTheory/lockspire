# Phase 125 - UI Design Contract

> Visual and interaction contract for Phase 125: Browser Proof, Docs & Adversarial Ratchet. Generated by gsd-ui-researcher for planner, executor, checker, and auditor use.

Phase 125 closes v1.32 by proving that the existing page-first admin polish is repeatable, accessible, responsive, redaction-safe, and bounded. This phase is a proof, docs, and adversarial-review phase. It must not add OAuth/OIDC behavior, storage schemas, public admin routes, public component labs, first-class browser tooling, CI browser gates, screenshot baselines, public theming, host-owned seams, new packages, or new mutation capabilities.

Sources: `AGENTS.md`, `.planning/STATE.md`, `.planning/ROADMAP.md`, `.planning/REQUIREMENTS.md`, `125-CONTEXT.md`, `125-RESEARCH.md`, prior Phase 122/123/124 UI specs, Phase 120 browser proof, Phase 121 scorecards, `brandbook/`, `lib/lockspire/web/admin_css.ex`, `lib/lockspire/web/components/admin_components.ex`, and existing `AdminLab` / `AdminProof` test support.

Implementation boundary:

- Preserve route truth as `Lockspire.Web.AdminRouter` plus exactly `/admin/clients/:client_id/edit?workflow=logout-propagation`.
- Use existing proof assets first: `RouteScorecards`, `HtmlAssertions`, `AdminLab.Fixtures`, `AdminLab.StressSurface`, `design_system_contract_test.exs`, `design_system_component_stress_test.exs`, and focused LiveView tests.
- Browser/manual evidence is maintainer-only supplemental proof after deterministic guardrails pass. It is not route truth, release truth by itself, public documentation truth, or package/runtime support.
- Do not add Playwright, axe, screenshot baseline tooling, Node package files, browser binaries, CI browser gates, trace/report workflows, or Hex package content in Phase 125.
- Do not create a public fixture route, Storybook/PhoenixStorybook route, public component API, public design-system docs, public theming API, host component registry, or browser-proof product surface.
- Do not edit `docs/supported-surface.md` unless implementation finds a concrete public-support ambiguity. The public ceiling must not gain lab, browser-proof, screenshot, public design-system, public theming, or AI judge promises.

Every Phase 125 proof or docs change must answer, in this order:

1. Which journey, route, or internal proof surface is being validated?
2. Which operator job or scorecard field does the proof protect?
3. Which deterministic guardrail backs the claim?
4. Which representative browser/manual note, if any, supplements the claim?
5. Which support-surface boundary prevents the proof artifact from becoming public runtime behavior?

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs / `--ls-space-1` | 4px | Badge internals, tiny inline state gaps, required-marker gaps |
| sm / `--ls-space-2` | 8px | Label-to-value gaps, compact metadata stacks, dense row internals |
| md / `--ls-space-4` | 16px | Default pane, form field, row, metric, evidence table cell, and action-cluster spacing |
| lg / `--ls-space-6` | 24px | Pane padding, proof section rhythm, route group spacing, confirmation-panel groups |
| xl / `--ls-space-8` | 32px | Admin body padding, page-hero spacing, major proof/doc section gaps |
| 2xl / `--ls-space-12` | 48px | Empty-state vertical padding and major route/proof breaks |
| 3xl | 64px | Reserved page-level separation only; do not introduce a new runtime token for Phase 125 |

Exceptions:

- Existing shipped compatibility values at 12px, 20px, and 40px may remain. Do not introduce new runtime spacing values for Phase 125 proof work.
- Standard inputs, buttons, button-like links, selects, checkboxes, and theme controls keep `--ls-control-height: 40px` minimum where touched.
- At widths below 720px, evidence-related admin surfaces must stack page hero actions, filter bars, form actions, pane headers, entity headers, dense rows, lifecycle rows, confirmation panels, and action groups vertically.
- Markdown proof artifacts may use normal Markdown table formatting. Do not translate Markdown table spacing into new runtime CSS.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px (`--ls-type-label-size`) | 600 | 1.2 |
| Body | 14px (`--ls-type-body-size`) | 400 | 1.5 |
| Heading | 16px (`--ls-type-heading-size`) | 600 | 1.25 |
| Display | 24px (`--ls-type-display-size`) | 600 | 1.2 |

Rules:

- New Phase 125 runtime UI copy, if any touched page needs minor proof-driven adjustment, uses exactly these four sizes and exactly two weights: 400 and 600.
- Existing heavier shell or legacy values may remain where already shipped, but Phase 125 must not expand the type scale.
- Use mono only for durable route paths, evidence paths, IDs, handles, timestamps, viewport dimensions, `scrollWidth`, `clientWidth`, URLs, token placeholders, and redacted proof values.
- Long mono values must render through `long_value`, `timestamp`, `copy_once_secret_panel`, or an existing wrapping class with `overflow-wrap: anywhere`.
- Page/proof headings use operator workflow language: `Orient`, `Configure`, `Support`, `Operate`, `Browser/manual evidence`, `Deterministic guardrails`, and `Adversarial signoff`.
- Avoid backend implementation headings such as `SQL rows`, `Oban internals`, `raw params`, `request object`, or `worker state` unless quoting an explicit forbidden-leakage check.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ls-surface-page`: light `#f8fafc`, dark `#0b1220` | Admin shell background and broad quiet page/proof surface |
| Secondary (30%) | `--ls-surface-panel`: light `#ffffff`, dark `#131c2e`; plus `--ls-surface-muted` | Page heroes, panes, rows, empty states, copy-once panels, confirmation panels, proof-note panels |
| Accent (10%) | `--ls-text-accent`: light Deep Cyan `#0e7490`, dark Signal Cyan `#22d3ee` | Active/current navigation, primary safe CTAs already approved by prior specs, selected route context, resource title links, proof route links, and focus-visible rings only |
| Destructive | `--ls-status-danger-*`: light text `#991b1b` / bg `#fee2e2`; dark text `#fca5a5` / bg `#2e1517` | Existing revoke/rotate/retire/disable confirmations, redaction failures, validation errors, terminal incident states, and adversarial `fail` rows only |

Accent reserved for: active/current navigation, route links in proof/doc surfaces, selected evidence context, primary safe CTAs already approved in Phases 122-124, and focus-visible rings. Accent must not be used for decorative proof panels, every badge, all metadata labels, normal body text, or screenshot-evidence decoration.

Status semantics:

| Status Group | Contract |
|--------------|----------|
| Success / pass | Deterministic guardrail passed, browser/manual row passed, active/healthy operator state. |
| Warning / gap | Manual evidence pending, optional browser automation deferred, warning posture, stale/read-only caveat. |
| Danger / fail | Redaction leakage, unsupported action drift, duplicate ID/focus/label failure, no-overflow failure, destructive/incident state. |
| Disabled / closed | Expired, revoked, already closed, unavailable action, stale/read-only evidence state. |
| Info / provenance | Evidence source, route source truth, maintainer-only proof note, public support boundary reminder. |

Color is never the only signal. Evidence rows must use text values such as `pass`, `fail`, `gap`, `blocked`, or `maintainer-only`; badges must include visible labels; docs must name the consequence and support boundary.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Runtime UI: no new command CTA is approved. Proof/docs primary verb phrase: `Run deterministic guardrails`. Evidence workflow labels: `Record browser evidence` and `Complete adversarial review`. |
| Empty state heading | `No browser evidence recorded yet` |
| Empty state body | `Run the deterministic guardrails first, then add redaction-safe route, viewport, theme, motion, focus, scroll-width, and client-width notes for the representative v1.32 matrix.` |
| Error state | `Proof evidence could not be validated. Fix the failing guardrail or redact the evidence note before using it for Phase 125 signoff.` |
| Destructive confirmation | none for Phase 125. Do not introduce new destructive runtime actions. Existing Support and Configure destructive confirmations keep their Phase 122 and Phase 124 copy contracts. |

Copy rules:

- Use the journey labels `Orient`, `Configure`, `Support`, and `Operate` exactly.
- Use proof nouns exactly: `scorecard`, `deterministic guardrail`, `browser/manual evidence`, `maintainer-only evidence`, `redaction-safe fixture`, `adversarial signoff`, and `public support ceiling`.
- Approved proof/doc action labels include `Run deterministic guardrails`, `Record browser evidence`, `Review scorecards`, `Review operator docs`, `Complete adversarial review`, and `Close v1.32 proof`.
- Do not introduce generic CTA drift: `Submit`, `Apply`, `OK`, `Open`, `Go`, `Continue`, `Manage`, `Learn more`, `Read more`, or `Click here`.
- Browser/manual evidence copy must say it is supplemental maintainer proof, not release truth by itself.
- Optional AI/persona judge prompts may be described only as advisory maintainer input with human signoff. They are not deterministic gates, release blockers, public support claims, or replacements for source/rendered/browser/manual proof.
- Error copy must avoid backend leakage and secret values. It must state which proof context failed and what to do next: rerun, redact, reload, or mark a gap.

## Fixture Matrix Contract

Use a hybrid fixture strategy:

| Fixture Layer | Required Scope | Contract |
|---------------|----------------|----------|
| `AdminLab.Fixtures` | Shared primitive/status/theme/motion/redaction coverage | Extend only when shared component stress needs missing states. Keep hostile values redaction-safe and test-only. |
| `AdminLab.StressSurface` | Internal component stress rendering | Cover page hero, entity header, metrics, decision summary, dense rows, lifecycle rows, forms, errors, copy-once, confirmation, long values, disabled links, and status badges without adding a public route. |
| Route-local LiveView fixtures | Support, Operate, and Configure page/JTBD proof | Add page-specific fixture states only where focused route proof needs domain-specific long data, missing fields, copy-once, closed states, incidents, or stale/read-only cases. |
| Browser/manual evidence rows | Representative v1.32 route matrix | Record scrubbed notes only after deterministic guardrails pass. Evidence rows must never preserve secrets or copy-once plaintext. |

Required state coverage:

| State Class | Required Values |
|-------------|-----------------|
| Cardinality and density | `empty`, one item, many items, dense/high counts, zero counts |
| String pressure | long names, long IDs, long URLs, long scopes, long endpoint values, long redacted handles |
| Optionality | missing optional fields, `Not recorded`, unknown-but-safe state labels |
| Lifecycle/security | warning, incident, disabled, expired, revoked, reuse-detected, copy-once, stale/read-only, already closed |
| Visual/accessibility | light, dark, system, reduced motion, keyboard focus, mobile widths |
| Journeys | Orient, Configure, Support, Operate, and internal lab boundary |

Fixture values must be obviously non-production and must not look like real tokens, real tenant hostnames, live API keys, private keys, cookies, authorization codes, user/device codes, verifier material, or plaintext credentials.

## Responsive And Accessibility Contract

- Representative browser/manual evidence must cover `320px`, `390px`, `768px`, `1024px`, and `1440px`.
- A no-page-overflow claim requires route, viewport, theme, motion, focus path, `scrollWidth`, `clientWidth`, result, and scrubbed notes.
- Touched admin surfaces must not require page-level horizontal scrolling at 320px.
- Below 720px, rows and forms stack in the order established by Phases 122-124: title/decision, status cluster, posture/consequence copy, long values, secondary metadata, then actions.
- Focus rings use existing `--ls-focus-ring-*` tokens and must not be removed.
- `aria-describedby`, `aria-labelledby`, and `aria-controls` targets must resolve when introduced.
- Every non-hidden form control must have an explicit label or accessible label.
- Status meaning never relies on color alone; badge text and surrounding consequence/proof copy are required.
- Reduced motion keeps orientation and focus feedback but neutralizes nonessential transforms and transitions through existing CSS.
- No icon-only actions, tooltip-only explanations, hover-only disclosures, or hidden proof notes are approved.

## Security And Redaction Contract

Never preserve or render these values in fixtures, rendered HTML, docs, proof artifacts, browser/manual notes, screenshots, traces, reports, flash copy, notices, or errors:

- access token plaintext, refresh token plaintext, token hashes, client secrets, registration access token plaintext, initial access token plaintext
- authorization codes, cookies, private keys, verifier material, PKCE material, state, nonce, raw device codes, raw user codes
- JWT-looking strings, `sk_live_`, `pk_live_`, production-looking tenant hostnames, production account identifiers, live customer domains
- source-only values such as `client_secret_hash`, private JWK text, raw request objects, raw response bodies, SQL rows, Oban IDs, worker internals, or endpoint secrets

Allowed evidence values:

- route paths, query workflow path, viewport widths, `scrollWidth`, `clientWidth`, theme/motion names, focus paths, scrubbed evidence paths, redacted handles, synthetic `.example.invalid` URLs, synthetic long IDs, counts, status labels, and command outcomes.

If evidence contains forbidden material, the required interaction is: delete the artifact or redact it, rerun the relevant guardrail, and record the sanitized gap or pass. Do not keep the original as hidden context.
