<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Key/client domain metadata -> rendered HTML | Public key/client metadata crosses into operator UI and must not include private key, secret, RAT, or verifier material |
| Operator confirmation -> lifecycle APIs | Key lifecycle and client lifecycle events are risky mutations and must keep confirmation/risk separation |
| Client action links -> host-mounted routes | Client action grouping must preserve existing route targets and not add host-owned staff policy behavior |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-17 | Information Disclosure | key and client detail pages | mitigate | render public/non-secret metadata only; preserve redacted secret/RAT display and copy-once panels |
| T-109-18 | Tampering | key publish/activate/retire and client toggle/rotation actions | mitigate | preserve existing event names/APIs and confirmation guards; separate danger actions through `confirmation_panel` and `action_group` destructive slots |
| T-109-19 | Repudiation | client action grouping | mitigate | label each group and action with noun-specific copy so operators can distinguish routine config, credentials/RAT, endpoint/logout, posture, and lifecycle effects |
| T-109-20 | Denial of Service | mobile key/client action layouts | mitigate | use `long_value` for long IDs/timestamps and `action_group` mobile stacking for dense actions |
| T-109-SC | Tampering | package manager installs | accept | no dependency installation or package-manager task is allowed in this plan |
</threat_model>
