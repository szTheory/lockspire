<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL params -> consent list query | Untrusted account/client/status filters enter LiveView and must stay normalized before `Admin.list_consents/1` |
| Consent domain data -> rendered HTML | Durable grant metadata crosses into operator HTML and must stay non-secret and wrapped |
| Operator confirmation -> revoke API | Dangerous consent revocation must require explicit confirmation and name non-secret target context |

## ASVS Level 1 / High-Block Gate

| Gate | Handling |
|------|----------|
| Baseline | OWASP ASVS 5.0.0 Level 1 |
| Block condition | Block plan completion on any unresolved HIGH issue in applicable ASVS categories. |
| Applicable categories | V4 Access Control for host-owned admin boundary preservation; V5 Input Validation for existing URL filter normalization; V6 Cryptography for grant/token/secret redaction and no plaintext exposure. |
| Executor handling | If implementation or tests reveal a HIGH security issue, stop execution and fix it before writing the summary; escalate only if the fix would require out-of-scope protocol, schema, or host-auth changes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-05 | Information Disclosure | `ConsentsLive.Index` and `ConsentsLive.Show` | mitigate | render only durable non-secret grant/client/account/scope metadata; assert secret/token plaintext and verifier material are absent |
| T-109-06 | Tampering | `revoke_consent` event | mitigate | preserve checkbox guard clause, existing Admin API, danger confirmation panel, and consequence-specific copy per D-18/D-19 |

| T-109-SC | Tampering | package manager installs | accept | no dependency installation or package-manager task is allowed in this plan |
