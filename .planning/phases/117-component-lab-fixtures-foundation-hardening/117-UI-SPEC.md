# Phase 117 - UI Design Contract

> Visual and interaction contract for Phase 117: Component Lab, Fixtures & Foundation Hardening. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Phoenix LiveView function components plus embedded Lockspire admin CSS |
| Preset | Not applicable; no shadcn, Tailwind, React Storybook, PhoenixStorybook, or third-party registry in this phase |
| Component library | `Lockspire.Web.Components.AdminComponents` with Phoenix `attr/3` and `slot/3` contracts |
| Icon library | None; do not introduce an icon dependency for the lab or fixtures |
| Font | `--ls-font-display` Familjen Grotesk stack for headings, `--ls-font-sans` Inter stack for UI/body, `--ls-font-mono` JetBrains Mono stack for identifiers |

**Source of truth:** `brandbook/`, `brandbook/tokens/tokens.css`, `brandbook/tokens/tokens.json`, `lib/lockspire/web/admin_css.ex`, `lib/lockspire/web/components/admin_components.ex`, Phase 116 inventories, and Phase 116 visual/lab contracts.

**Stack contract:** Phase 117 targets Phoenix `1.8.5` and Phoenix LiveView `1.1.28` admin surfaces. Preserve the embedded-library boundary: host apps own operator authentication, MFA, roles, tenant policy, layouts, branding, and public developer portal UX; Lockspire owns only the mounted admin/protocol surfaces after host authorization.

**Lab/tooling contract:** The component lab is maintainer/demo/test-only. It may use ExUnit-rendered HEEx/function components, repo-local fixture modules, and optional quarantined browser proof tooling, but it must not mount through `Lockspire.Web.AdminRouter`, add a supported admin route, publish a public API, add a public theming engine, or create a host-editable registry.

## Spacing Scale

Declared values use the existing `--ls-space-*` tokens and remain multiples of 4px:

| Token | Value | Usage |
|-------|-------|-------|
| xs / `--ls-space-1` | 4px | Inline badge gaps, focus/label spacing, tight status clusters |
| sm / `--ls-space-2` | 8px | Compact element spacing, button vertical padding, badge padding |
| md / `--ls-space-4` | 16px | Default component spacing, card padding, field grouping |
| lg / `--ls-space-6` | 24px | Lab state sections, page group spacing, major form grouping |
| xl / `--ls-space-8` | 32px | Lab layout gaps, shell/header spacing, major admin groups |
| 2xl / `--ls-space-12` | 48px | Lab scenario group breaks and page-level route separation |
| 3xl | 64px | Reserved for page-level spacing only; do not add a new token unless later implementation proves the need |

Exceptions:

- `--ls-space-3` is allowed for existing 12px compact rows, labels, and mobile-sensitive resource rows.
- `--ls-space-5` is allowed for existing 20px card/body rhythm.
- `--ls-space-10` is allowed for existing 40px shell or control-related gaps.
- `--ls-control-height` remains 40px for form controls and buttons. Lab fixtures must not introduce smaller click targets.
- Stress states may use tighter grouping only inside already-existing components; do not add arbitrary one-off spacing values.

## Typography

Use exactly these four sizes and two weights in the contract:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px / `--ls-type-label-size` | 600 | 1.2 |
| Body | 14px / `--ls-type-body-size` | 400 | 1.5 |
| Heading | 16px / `--ls-type-heading-size` | 600 | 1.25 |
| Display | 24px / `--ls-type-display-size` | 600 | 1.2 |

Rules:

- Body text uses the Inter stack via `--ls-font-sans`.
- Headings use the Familjen Grotesk display stack where existing admin CSS applies it.
- Identifiers, token handles, URLs, JWK/thumbprint-like values, scopes, timestamps, and long protocol strings use the JetBrains Mono stack via `--ls-font-mono`.
- Do not add new font files, external font fetches, viewport-scaled type, or dynamic text shrinking.
- Long identifiers must wrap through layout, `long_value`, code-block, resource-row, or table/list alternative patterns.

## Color

Use brandbook semantic tokens as the canonical color contract. Phase 117 may harden token declarations and aliases, but component styles must consume semantic aliases rather than raw primitive colors.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light: `--ls-surface-page` `#f8fafc`; Dark: `--ls-surface-page` `#0b1220` | Page background, lab shell body, broad route surfaces |
| Secondary (30%) | Light: `--ls-surface-panel` `#ffffff`; Dark: `--ls-surface-panel` `#131c2e` | Cards, lab scenario sections, resource rows, nav/shell panels |
| Accent (10%) | Light text/action: Deep Cyan `#0e7490`; Dark/hero/focus/non-text: Signal Cyan `#22d3ee` | Focus rings, primary actions, active navigation, key status emphasis, hero/brand accents |
| Destructive | Light: `--ls-status-danger-*` with text `#991b1b`; Dark: `--ls-status-danger-*` with text `#fca5a5` | Destructive buttons, destructive confirmations, danger badges and alerts only |

Accent reserved for:

- Primary CTAs in lab and admin workflow states.
- Focus ring and focus glow.
- Active navigation/selected route states.
- Non-text brand/focus accents on dark surfaces.
- Status/info emphasis where semantic `info` tokens apply.

Accent is not reserved for all links, all badges, all borders, table decoration, or generic lab chrome. Signal Cyan `#22d3ee` must not be used as normal light-mode text or small light-mode UI; use Deep Cyan `#0e7490` or `#155e75` for light-mode text/actions.

Status color rules:

- Every status badge and state cluster must include visible text; color alone is insufficient.
- Lab fixtures must exercise healthy, warning, incident, disabled, self-registered, expired, revoked, reuse-detected, copy-once, empty, dense, and long-value states.
- Warning, danger, success, and info states must use semantic status tokens, not raw hex outside token declarations.
- Light, dark, and system behavior must be first-class. System follows `prefers-color-scheme`; explicit `[data-theme="light"]` and `[data-theme="dark"]` hooks may force a mode for lab/proof.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Render stress surface` |
| Empty state heading | `No lab scenarios rendered` |
| Empty state body | `Load the maintainer fixtures before browser proof so empty, dense, error, destructive, and long-value states render from the same source.` |
| Error state | `Component lab proof drifted from the design-system contract. Re-render the stress surface with current AdminComponents, admin CSS, and redaction-safe fixtures before changing production pages.` |
| Destructive confirmation | `Revoke token family`: `Revoking this family invalidates all active refresh tokens for the selected client and account. Type the client ID before continuing.` |

Microcopy rules:

- Use concise, domain-accurate, consequence-oriented operator language.
- Lab labels should name the state under test directly: `Empty clients`, `Dense token rows`, `Reuse detected`, `Copy-once credential`, `Disabled action`, `Long redirect URI`, `Dark mode`, `Reduced motion`.
- Preserve journey nouns from prior phases: `DCR onboarding`, `DCR policy`, `post-logout redirect URIs`, `logout propagation URIs`, `registration access token`, `initial access token`, `refresh family`, `logout deliveries`.
- Avoid fear language and generic security-dashboard wording such as `threat center`, `attack map`, `military-grade`, `lock it down`, or decorative shield/lock tropes.
- Operation queues remain truthful about read-only support unless existing domain APIs back an action. Do not add retry/discard/logout controls as lab examples unless they already exist in runtime APIs.

## Component Lab Contract

| Scope Item | Contract |
|------------|----------|
| Purpose | Stress real Lockspire admin components, recurring groups, CSS foundations, and hostile but redaction-safe data before production page polish. |
| Classification | `internal_lab`, `test_only`, or `demo_only`; never `admin_supported`. |
| Rendering shape | Prefer Lockspire-owned Phoenix component stress modules and ExUnit-rendered HEEx/function components. Demo-only page proof is allowed only outside supported router truth. |
| Route boundary | The lab must not add `component_lab`, `design_system_lab`, or similar paths to `Lockspire.Web.AdminRouter`. |
| Public surface boundary | The lab must not appear in `docs/supported-surface.md`, public API docs, or host integration promises as a supported admin route. |
| Package boundary | Keep browser harness scaffolding outside Hex package files unless a later explicit packaging decision changes that boundary. |
| Tooling | PhoenixStorybook, React Storybook, Tailwind, shadcn, and third-party visual registries remain out of scope for Phase 117. |

Primary visual priority:

- The stress-surface matrix header is the screen anchor. It must show the active component group, theme, motion mode, and fixture set before any preview content.
- The active scenario preview is the second focal point. It should carry the densest visual weight inside the lab body, while surrounding matrix controls stay compact and scan-first.
- Supporting inventory, fixture, and proof metadata must not visually outrank the matrix header or active scenario preview.

Minimum lab matrix:

- Component states: normal, empty, error, disabled, destructive, long-value, dense-data, copy-once, redacted.
- Theme states: light, dark, system.
- Motion states: default motion and reduced motion.
- Status states: healthy, warning, incident, disabled, self-registered, expired, revoked, reuse-detected.
- Layout states: narrow/mobile stress, dense row stress, table/list alternative pressure, long URL/scope/identifier wrapping.
- Focus states: keyboard focus on links, buttons, destructive actions, copy-once panels, form controls, and resource-row actions.

## Fixture And Redaction Contract

| Fixture Area | Required States |
|--------------|-----------------|
| Clients | Healthy confidential client, disabled client, self-registered client, long client ID/name, long redirect URI, logout propagation URI, no redirect URI empty state |
| Tokens | Active, expired, revoked, reuse-detected, dense results, long token handle, refresh family destructive confirmation |
| Consents | Remembered, revoked, empty filtered result, long account/client identifiers |
| Keys | Active, upcoming, retiring, retired, warning lifecycle state |
| DCR/IAT | Disabled DCR, open/self-registration warning, active IAT, expired IAT, revoked IAT, copy-once initial access token placeholder |
| Operations | Empty interactions, pending login, pending consent, pending device authorization, expired device authorization, logout delivery failed/retryable/discarded read-only rows |

Redaction rules:

- No plaintext client secrets, registration access tokens, initial access tokens after creation, refresh/access tokens, authorization codes, cookies, private keys, verifier material, user codes, or unredacted sensitive values may appear in fixtures, screenshots, logs, docs, or lab output.
- Copy-once states must use safe placeholders that cannot be mistaken for real credentials. Stored states must render `Redacted`, hash/handle-only text, or intentionally fake values.
- Long hostile data should use `.example.invalid`, `client_...`, `acct_...`, `tok_...`, and similar fake namespaces.

## Foundation Hardening Contract

| Foundation | Contract |
|------------|----------|
| Light color scheme | Explicit light behavior must exist for default/root or `[data-theme="light"]` contexts. Light surfaces must preserve Deep Cyan for text/action accent. |
| Dark color scheme | Dark mode remaps semantic aliases only. Primitive color tokens remain stable; component CSS must not invert primitives locally. |
| System mode | `prefers-color-scheme` is honored unless an explicit data-theme override is present. |
| Surface/elevation | Dark panels and elevated surfaces must remain distinguishable from the page background without heavy decorative shadows. |
| Motion | Use explicit transition properties only. `transition: all` is forbidden. Motion is short, purposeful feedback: 150ms for controls and 220ms for larger surface changes. |
| Reduced motion | `prefers-reduced-motion: reduce` neutralizes animation/transition duration and active transforms. The UI remains understandable without movement. |
| Focus | Visible focus uses `--ls-focus-ring-*`, is not clipped, and remains contrast-safe in light and dark modes. |
| Responsive | No page-level horizontal overflow at 320px, 390px, 768px, 1024px, or 1440px proof widths. |
