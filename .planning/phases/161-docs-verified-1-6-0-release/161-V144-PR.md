Closes milestone v1.44 (Adopter Polish), phases 158-161. It makes the first run of a new install less surprising and tells operators plainly whether their signing keys are protected. The upgrade is non-breaking: no new Hex dependencies, no schema migration and no OAuth/OIDC behavior change.

## Code changes
- **Repo start (phase 158):** three named commands now start and stop the host app's repo themselves and report the real reason when that fails, instead of crashing with a raw exception:
  - `mix lockspire.client.create`
  - `mix lockspire.doctor token_format`
  - `mix lockspire.doctor remote-jwks`

  `mix lockspire.keys.reencrypt` is unchanged and still deferred: it keeps its existing behavior.
- **Key-encryption key setup (phase 159):**
  - New `mix lockspire.gen.kek` prints a fresh key-encryption key once, plus the `config/runtime.exs` block that reads it from the environment. It is the only place a key is ever printed.
  - `config :lockspire, :key_encryption` accepts `{:system, "VAR"}` entries; a missing or blank variable fails boot with a message that names the variable, never a value.
  - The key set no longer shows key material when inspected, and the install and upgrade guidance points to the new command.
- **Admin Keys page (phase 160):** a read-only "Key protection" line says whether the signing keys are protected, plus a calm message when generating a key fails because no encryption key is set. PRODUCT.md vocabulary map updated in the same change.
- **Docs and release (phase 161):** the key protection operator guide and the upgrade guide are updated, and the planning records for 1.6.0 are prepared.

## Release-gate repair (needed before 1.6.0 can ship)
The release-train ledger check in `scripts/maintainer/repo_hygiene_check.sh` required the ledger's Release Please metadata version to equal the public Hex version. Once the 1.6.0 release PR merges, metadata is 1.6.0 while the public package is still 1.5.1 until publication, so the check would block the release. The metadata-vs-public clause now accepts metadata at or above the public version; public, artifact, tag and SHA equality stay strict, and lower metadata or inconsistent evidence still blocks. The matching contract helpers in `test/support/lockspire/release_proof/` now read their expected facts from the ledger file instead of pinning 1.5.1. Separately, `test/support/mix_repo_helpers.ex` is a new test helper for the repo-start tests; it is not part of the gate repair.
