because it is the scope the protected route pipeline requires — whose allowed grant types include
`authorization_code`, and whose token endpoint auth method is `none`.

nothing to sign with after a stock install. Record that omission as FAIL attributed jointly to the

`# LOCKSPIRE_WALK_WORKAROUND: ADOPT-D06`. Immediately assert the outcome rather than assuming it:

undocumented calls were required as a sub-observation on the same ledger entry — that is RESEARCH Open
Question 1 resolving in either direction, and both directions are evidence.

Then the boot and drive block, reproducing the CI shape: create the workdir if missing, start
`mix phx.server` in the generated app in `MIX_ENV=dev` with stdout and stderr redirected to
`<workdir>/server.log`, capture the pid, and install the pid-only trap on `EXIT`, `INT` and `TERM`

`step-06c-token-proof` appear in the single report and count toward the single verdict. Print `<workdir>/server.log` to the terminal when the driver reported any FAIL. The
log stays in the gitignored workdir; it must never be copied into a committed artifact, because it can
contain authorization codes, access tokens and the seeded password.

126-01). When `--keep` is passed, leave the server running, print the base URL so the maintainer can

the preflight of any subsequent run will reject that bound port as a prerequisite failure. The
evidence tree — workdir, generated host, `server.log`, step markers — survives either way and needs no
flag (D-20). Leaving a server running by default would violate this plan's own "terminates only what
it started" prohibition and T-126-25, so the default path always tears the server down.
