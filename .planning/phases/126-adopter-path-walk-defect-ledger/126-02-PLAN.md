`step-03b-router-call` — follow the guide literally. Import the generated `HostAppWeb.Router.Lockspire`

distinction in the detail — "compiles clean, zero routes defined" — and attribute it to the installer
as `ADOPT-D01`. Do not let a clean compile be recorded as PASS; exit-code success is precisely the
failure mode ADOPT-04 and this step exist to catch.

`step-03b-router-paste` — apply the other interpretation a human reader of the heredoc would take:
paste the string's contents into the host router. Assert compilation. The expected observation is a
FAIL with the error `the pipeline :require_operator has not been defined`, because that pipeline does
not exist in a stock generated router. Record FAIL with the error class, attribute it to the installer
as `ADOPT-D02`, and continue. Because this sub-step deliberately puts the host into a
non-compiling state, it must restore the host to the previous state before returning so
`step-03b-router-wire` starts from a known point.

`step-03b-router-wire` — apply the smallest real wiring needed for the walk to reach `step-04`, marked

when `mix phx.routes` in the generated app shows the Lockspire mount, the interaction routes, and the
consent LiveView route; otherwise FAIL with the missing route named.

Keep all three sub-steps inside the record-and-continue idiom. Aborting at the first FAIL here would
