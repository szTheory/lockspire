<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Repository → isolated package input | Source files cross into the purported consumer environment. |
| Child processes/HTTP → harness diagnostics | Sensitive OAuth material can enter stdout, stderr, exceptions, and retained evidence. |
| Harness → operating system | Ports, processes, temp paths, and credentials must not survive termination. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-133-01 | Tampering | package/dependency provenance | high | mitigate | Unpacked inventory, checked-in locks, `--check-locked`, and child dependency provenance reject checkout/test-support or lock drift. |
| T-133-02 | Information disclosure | diagnostics/evidence | high | mitigate | Redact before formatting or retention and sentinel-scan all outputs. |
| T-133-03 | Denial of service | process lifecycle | medium | mitigate | Bound readiness, track/reap both PIDs, and test signal/startup-failure cleanup. |
| T-133-04 | Spoofing | origin allocation | medium | mitigate | Bind loopback-only unique ports and verify each expected readiness endpoint. |
| T-133-25 | Tampering | child dependency cache | high | mitigate | Restrict reuse to role-scoped external dependencies, validate cache containment/provenance, and keep child builds fresh. |
</threat_model>
