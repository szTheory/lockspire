<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser callback → client backend | Attacker-controlled code/state/error parameters cross into the confidential client. |
| Provider metadata/tokens → client verifier | Remote discovery, keys, JWT, and userinfo become local session authority. |
| Client database → callback worker | Durable secret transaction material is read and terminally consumed. |
| Bootstrap configuration → authorization routes | Separate bearer and DPoP credentials become a server-selected transaction profile. |
| DPoP transaction/session → provider token and userinfo | An encrypted private key signs endpoint-specific proofs while nonce domains and token binding remain exact. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-133-09 | Spoofing/Tampering | callback state | critical | mitigate | Independent server-side state and atomic consumption before exchange, including concurrency/restart tests. |
| T-133-10 | Spoofing | ID token | critical | mitigate | Discovery-bound issuer/JWKS/algorithms, exact kid selection, strict JOSE verification, aud/exp/nonce checks. |
| T-133-11 | Spoofing | userinfo | high | mitigate | Request only after token validation and require exact subject equality. |
| T-133-12 | Information disclosure | transaction/error paths | high | mitigate | Keep verifier/nonce/secrets server-side and expose only allowlisted safe error classes. |
| T-133-24 | Elevation of privilege | client-profile selection | high | mitigate | Fixed routes persist server-selected profiles; request input cannot choose or substitute a client id/secret. |
| T-133-26 | Information disclosure | DPoP key/session ownership | critical | mitigate | Encrypt server-side key/token state, expose only opaque handles, clear terminal/transaction copies, and sentinel-scan every diagnostic. |
| T-133-27 | Spoofing | token/userinfo DPoP nonce domains | critical | mitigate | Exact endpoint htu/htm/ath, independent nonce challenges, fresh retry proofs, binding-JKT equality, and bounded retries. |
| T-133-28 | Elevation of privilege | DPoP session handoff | high | mitigate | Atomic transaction-to-session transfer, rotated opaque handle, fixed server-selected profile, and no client-controlled key/token inputs. |
</threat_model>
