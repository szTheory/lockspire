<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Host/operator attributes → direct client persistence | Untrusted client shape and key metadata crosses into durable authentication configuration. |
| DCR JSON → policy/registration/persistence | Remote registrants supply grants, responses, redirects, scopes, and cryptographic key locations. |
| Registered redirect list → authorization request | Runtime browser redirect safety depends on exact stored membership. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-132-04 | Spoofing / Elevation of privilege | device-only redirect exception | high | mitigate | Capability matrix requires redirects when either authorization-code grant or code response exists; direct, DCR, and runtime negative tests prove it. |
| T-132-05 | Spoofing | private_key_jwt registration | high | mitigate | Require confidential client, exactly one safe key source, allowed non-none algorithm, and persisted key material. |
| T-132-06 | SSRF | jwks_uri intake | high | mitigate | Preserve HTTPS-only metadata checks and existing guarded remote-JWKS resolver; reject unsafe schemes before persistence. |
| T-132-07 | Information disclosure | direct/DCR errors and telemetry | medium | mitigate | Translate only field/reason data and assert raw key sentinels do not appear. |
| T-132-08 | Repudiation | shared validation adapters | medium | mitigate | Preserve registration success/rejection telemetry and deterministic boundary-specific error shapes. |
