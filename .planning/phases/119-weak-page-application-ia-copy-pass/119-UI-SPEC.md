## Visual Language

Phase 119 applies the strengthened admin design system to weak production routes. The UI must read as calm, dense operator software: grouped panes, entity headers, lifecycle rows, workflow shells, compact resource rows, and precise consequence copy. This phase is page/group polish, not a redesign of the shell.

Required visual qualities:

- Keep the admin journey model visible: Configure pages state posture and next safe configuration action; Support pages prioritize investigation context and guarded revocation; Operate pages show read-only queue truth.
- Replace one-large-card or raw local-section drift with `entity_header`, `pane`, `workflow_shell`, `status_cluster`, `action_group`, `lifecycle_row`, `dense_resource_row`, `resource_list`, `long_value`, and existing confirmation/copy-once primitives.
- Client detail must separate identity/current status, effective posture, credentials/assertion keys, endpoints/logout, DCR/RAT context, support pivots, and lifecycle/destructive actions.
- DCR policy must feel like one coherent policy workflow split into gate, allowlist, lifetime, auth-method, and risk/posture decision groups.
- IAT, token, consent, device authorization, interaction, and logout queue pages must state page job, primary decision, empty state, risk state, and next safe action without adding unsupported behavior.
- Signal Cyan stays restrained. Use Deep Cyan `#0e7490` for light-mode action text/fills and Signal Cyan `#22d3ee` for dark-mode accent, focus, logo, and large non-text signal only.
- No generic security tropes: no shields, threat-center metaphors, panic copy, novelty console styling, or fear-led warnings.
- Long IDs, URLs, handles, timestamps, scopes, and redacted values must wrap through `long_value`, resource rows, list alternatives, or existing wrapping CSS without horizontal page overflow.

## Spacing Scale

Declared values are the existing 4px baseline scale for new Phase 119 layout decisions:

| Token | Value | Usage |
|-------|-------|-------|
| `--ls-space-1` | 4px | Dot gaps, required markers, tight inline rhythm |
| `--ls-space-2` | 8px | Badge gaps, help/error gaps, compact metadata gaps |
| `--ls-space-4` | 16px | Default element spacing, row metadata gaps, compact section padding, action clusters |
| `--ls-space-6` | 24px | Pane, workflow-shell, entity-header, and ordinary page group padding |
| `--ls-space-8` | 32px | Page body padding and major page group gaps |
| `--ls-space-12` | 48px | Empty-state vertical padding and major group breathing room |
| `3xl` | 64px | Reserved maximum page-level separation; do not introduce for ordinary Phase 119 panes or rows |

Exceptions:

- Existing shipped compatibility values at 12px, 20px, and 40px may remain where current CSS already uses `--ls-space-3`, `--ls-space-5`, `--ls-space-10`, or `--ls-control-height`. Do not add new page-local spacing values.
- Control minimum height stays `--ls-control-height: 40px`.
- Pane/card radius stays `--ls-radius-lg` (8px) or less. Badge pills may keep the existing `9999px` radius.
- Dense queue rows may use `--ls-space-2` internal gaps only when metadata, statuses, and actions still wrap cleanly on narrow widths.

Rules:

- Text must wrap within buttons, panes, dense rows, and confirmation copy. Do not shrink text to avoid overflow.
- Existing legacy heavier weights may remain where already shipped; new Phase 119 markup should use only regular 400 and semibold 600.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ls-surface-page` light `#f8fafc`, dark `#0b1220` | Page background and broad admin shell |
| Secondary (30%) | `--ls-surface-panel` light `#ffffff`, dark `#131c2e`; `--ls-surface-muted` | Panes, workflow shells, rows, filters, empty states, form shells |
| Accent (10%) | Light Deep Cyan `#0e7490`; dark Signal Cyan `#22d3ee` | Primary buttons, text links, active nav underline, focus rings, restrained info/status borders |
| Destructive | `--ls-status-danger-*` semantic aliases | Destructive buttons, destructive confirmation panels, validation/error states, terminal security failures |

Accent reserved for:

- Primary CTA buttons: `Save global DCR policy`, `Mint initial access token`, and existing primary workflow actions.
- Text links and active/current navigation state.
- Focus rings and focus glow.
- Dark-mode primary button fill.
- Restrained status/info borders where semantic info state is required.

Accent must not be used for generic decoration, all interactive elements, normal light-mode body text, small low-contrast icons, or route backgrounds.

Status rules:

- Status meaning must be expressed through badge text, row labels, and consequence copy. Color alone is never sufficient.
- Real Configure, Support, and Operate statuses must map intentionally through `status_badge`; unknown fallback may remain disabled only for truly unknown values.
- Use `domain={:device_authorization}` when `:approved` means approved-but-waiting in the device authorization queue.
- Use semantic status aliases for healthy, waiting, warning, danger, completed, provenance, disabled, expired, revoked, retryable, discarded, skipped, succeeded, rendered, consumed, pending login, and pending consent.

## Page And Interaction Contracts

### Client Detail

Target: `lib/lockspire/web/live/admin/clients_live/show.ex`

Required structure:

- Keep `page_hero` with Configure journey framing.
- Replace the single large client `section_card` body with an `entity_header` followed by intentional panes or lifecycle rows.
- Entity header title is the client name or client ID; identifier is the client ID rendered through `long_value`; status lives in a `status_cluster`.
- Required groups, in this order unless implementation proves a cleaner scan path:
  1. Identity and current status
  2. Effective posture
  3. Credentials and assertion keys
  4. Endpoints and logout
  5. DCR and RAT context
  6. Support pivots
  7. Lifecycle and destructive actions
- Preserve the vocabulary split: post-logout redirect URIs are browser destinations; logout propagation URIs are RP cleanup endpoints.
- Preserve distinct DCR onboarding, self-registered provenance, and RAT support; do not collapse these into DCR policy.

Interaction contract:

- Preserve existing patch destinations and events: routine edit, redirect URI edit, post-logout redirect URI edit, logout propagation query workflow, PAR policy edit, security profile edit, secret rotation, RAT rotation, and `toggle_client`.
- Use `action_group` slots to keep routine, secondary, credential, and destructive actions visually separated.
- Use `lifecycle_row` for enable/disable and rotation context when it improves consequence scanning.
- Disable client belongs in the destructive slot with adjacent consequence copy. Enable client may remain a lifecycle recovery action but must not appear as a high-risk destructive action.
- Secret and RAT plaintext may appear only in existing copy-once rotation states; follow-up states must show redacted material or handles.

### DCR Policy Workflow

Targets: `lib/lockspire/web/live/admin/policies_live/dcr.html.heex`, `dcr.ex`, and `dcr/policy_form.ex`

Required structure:

- Keep one submitted form with `phx-submit="save_policy"`.
- Do not rename, split, remove, or duplicate current `policy[...]` field names.
- Wrap decision groups in `workflow_shell` or equivalent pane chrome inside the one form.
- Replace remaining raw `lockspire-admin-field` wrappers with `form_field` wherever practical.

Decision groups and fields:

| Group | Required fields/copy |
|-------|----------------------|
| Gate | `policy[registration_policy]`; copy must explain disabled, initial access token, and open without fear language. |
| Allowlist | `policy[dcr_allowed_scopes]`, `policy[dcr_allowed_grant_types]`, `policy[dcr_allowed_response_types]`, `policy[dcr_allowed_redirect_uri_schemes]`, `policy[dcr_allowed_redirect_uri_hosts]`. |
| Lifetime | `policy[dcr_default_client_lifetime_seconds]`, `policy[dcr_default_client_secret_lifetime_seconds]`, `policy[dcr_default_registration_access_token_lifetime_seconds]`. |
| Auth method | `policy[dcr_allowed_token_endpoint_auth_methods]`; preserve private-key-jwt and client-secret-jwt posture copy. |
| Risk/posture | Existing descriptive copy that explains current issuer posture and what this page does not create. |

Interaction contract:

- Primary CTA label is `Save global DCR policy`.
- Preserve `PolicyForm.changeset/2` and `Admin.put_dcr_policy/1` behavior.
- Do not add registration modes, auth methods, policy values, automatic risk actions, migrations, or storage changes.
- Error copy uses `Review the highlighted policy fields` plus field-level repair text.

### Initial Access Tokens

Targets: `lib/lockspire/web/live/admin/iat_live/index.html.heex`, `new.html.heex`, and `index.ex`

Required structure:

- Keep the page job as DCR onboarding intake, not general DCR policy.
- Keep metrics for active, used, expired, revoked, and total intake.
- Use `pane`, `resource_list`, `dense_resource_row`, `form_field`, and `workflow_shell` where they improve scanability without changing event or field names.
- IAT index rows must expose creator, expiration, last state change, usage/limit, and status through non-secret handles and wrapping values.
- IAT new form must preserve `single_use`, `expires_in_days`, `phx-submit="mint"`, and the copy-once reveal/acknowledge flow.

Interaction contract:

- Primary CTA stays `Mint initial access token`.
- Secondary navigation/action copy stays `Review initial access tokens`.
- Copy-once panel body: `Copy this value now. Lockspire stores only the hash after this response.`
- Destructive CTA stays `Revoke initial access token`; confirmation must name the redacted IAT handle and consequence for DCR intake.
- Plaintext IAT appears only immediately after minting and only inside `copy_once_secret_panel`.

### Support Details

Targets: `lib/lockspire/web/live/admin/tokens_live/show.ex` and `lib/lockspire/web/live/admin/consents_live/show.ex`

Required structure:

- Apply targeted primitive/copy alignment only where it improves incident hierarchy, mobile readability, or consequence scanning.
- Token detail should separate token identity/current state, refresh family lineage, and corrective actions.
- Consent detail should separate durable grant identity/current state, scope context, and revoke consequence.
- Use `entity_header`, `pane`, `status_cluster`, `description_list`, `long_value`, `resource_list`, `dense_resource_row`, and `confirmation_panel` without changing current events.

Interaction contract:

- Preserve `Admin.revoke_token/2`, `Admin.revoke_token_family/2`, `Admin.revoke_consent/2`, `phx-submit="revoke_token"`, `phx-submit="revoke_family"`, and `phx-submit="revoke_consent"`.
- Revoke token copy must keep single-token scope distinct from family-wide scope.
- Revoke token family copy must name family-wide refresh-token invalidation and the inability to recover plaintext token material.
- Revoke consent copy must name future remembered-consent reuse as the durable consequence.
- Do not render access/refresh token plaintext, token hashes, authorization codes, cookies, verifier material, private keys, or raw credential material.

### Operate Queues

Targets: `lib/lockspire/web/live/admin/device_authorizations_live/index.ex`, `interactions_live/index.ex`, and `logout_deliveries_live/index.ex`

Required structure:

- Queue pages remain read-only operator surfaces.
- Use `pane`, `resource_list`, and `dense_resource_row` for row content. Do not wrap `resource_list` rows in `lockspire-admin-table-wrap` unless a real table is rendered.
- Device authorization rows show client, subject, redacted handle, expiration, and status without exposing device code or user code material.
- Interaction rows show interaction ID, client, subject, prompt, created, expires, and status through `long_value` and redacted handles.
- Logout delivery rows show delivery ID, client, endpoint, attempts, timestamp, channel, and status through `long_value`.
- Empty states must state that no records are waiting for operator review.

Interaction contract:

- Do not add retry, discard, approval, logout, worker-control, or queue mutation UI unless an existing domain API already backs it and tests prove the route/event contract.
- Page copy may use `review`, `inspect`, `verify upstream state`, and `wait for protocol flow`; it must not imply manual retry/discard/approval actions.
- Failed/retryable/discarded statuses may be risk states, but the next safe action is review/context, not a new button.

## Responsive Behavior

Phase 119 implementation must preserve the Phase 120 browser-proof targets even though Phase 120 owns full browser evidence:

- No page-level horizontal overflow at 320px, 390px, 768px, 1024px, or 1440px.
- Entity headers, pane headers, workflow-shell actions, lifecycle rows, dense resource rows, and action groups must stack cleanly at narrow widths using existing CSS behavior.
- Destructive action groups stack below primary/secondary actions with the existing separator on narrow screens.
- Long URLs, client IDs, account handles, token handles, interaction IDs, delivery IDs, scopes, timestamps, and redacted values wrap using `long_value` or equivalent CSS.
- True comparison tables may remain in `lockspire-admin-table-wrap`; list content must use list/row chrome instead of fake table wrappers.
- Secondary navigation, filters, and action clusters must wrap without clipping text or controls.

## Accessibility

Phase 119 must preserve the existing WCAG floor:

- AA contrast for text and non-text controls in light, dark, and system modes.
- Status and risk meaning is visible in text, not color alone.
- Focus-visible rings remain visible, offset, and contrast-safe on buttons, links, form controls, row actions, secondary nav, and destructive controls.
- `form_field` help and error copy must be associated with inputs through deterministic IDs where practical.
- User-correctable validation uses an error summary plus field-level errors.
- Disabled links expose disabled semantics and are not keyboard-activatable.
- Destructive confirmations name the durable consequence before the destructive action.
- No duplicate IDs in grouped DCR policy fields or IAT forms.
- Operate queues must not expose raw secret-like material to assistive technology labels or titles.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Save global DCR policy` for the DCR workflow; preserve specific existing CTAs such as `Mint initial access token`, `Revoke token family`, and `Revoke consent grant` |
| Empty state heading | `No {resource} waiting for review` for operate queues; `No initial access tokens minted` for true IAT zero state; `Client not found`, `Token not found`, or `Consent grant not found` for missing detail records |
| Empty state body | Operate queues: `There are no {workflow records} waiting for operator review.` IAT: `Mint a token to allow partners to dynamically register clients.` Missing detail: `Lockspire could not load that {record} from durable storage.` |
| Error state | `Review the highlighted policy fields, then save again.` Field-level errors must name the repair path, such as `Enter a positive lifetime in seconds.` |
| Destructive confirmation | `Revoke token family: This family-wide action revokes every active token in the refresh lineage and cannot recover plaintext token material.` |

Route-specific copy rules:

- Client detail page job: `Review identity, effective posture, credentials, endpoints, DCR context, and lifecycle actions for this client.`
- DCR policy page job: `Configure issuer registration posture for Dynamic Client Registration without changing existing client records.`
- IAT page job: `Review DCR onboarding intake tokens by status, expiration, creator, usage limit, and safe revocation context.`
- Device authorization page job: `Triage device-flow state without exposing device or user code material.`
- Interaction page job: `Review authorization interaction state by status, client, subject, age, expiration, and safe review context.`
- Logout delivery page job: `Review logout delivery work and status pressure without adding worker controls.`

Tone rules:

- Use OAuth/OIDC nouns: client, consent grant, token family, initial access token, registration access token, device authorization, interaction, logout delivery, redirect URI, post-logout redirect URI, logout propagation URI.
- Avoid vague CTAs such as `Submit`, `Continue`, `Go`, `Manage`, and `Fix`.
- Avoid fear language such as `dangerous`, `critical breach`, `panic`, `threat center`, or `attack map`.
- Consequence copy names what changes durably and what remains unrecoverable. It does not speculate about host tenant policy.

Destructive or high-risk actions in scope:

| Action | Confirmation approach |
|--------|-----------------------|
| Disable client | Place in client lifecycle/destructive pane with adjacent consequence copy; preserve `toggle_client`. |
| Rotate client secret | Existing rotation flow and copy-once panel; plaintext shown once only. |
| Rotate registration access token | Existing checkbox confirmation and copy-once panel; plaintext shown once only. |
| Revoke initial access token | Existing `data-confirm` or equivalent rendered confirmation that names redacted IAT handle and DCR intake consequence. |
| Revoke token | Existing `confirmation_panel` plus checkbox confirmation; names single-token scope. |
| Revoke token family | Existing `confirmation_panel` plus checkbox confirmation; names refresh-family-wide invalidation. |
| Revoke consent grant | Existing `confirmation_panel` plus checkbox confirmation; names future remembered-consent reuse consequence. |

No destructive or mutating operate-queue action is in scope.

## Component Usage Contract

Use existing `Lockspire.Web.Components.AdminComponents` primitives. Do not create a second design-system layer.

| Component | Phase 119 contract |
|-----------|--------------------|
| `page_hero` | Every touched route keeps journey eyebrow, precise page job, optional summary, and specific actions. |
| `entity_header` | Use for client detail and optionally token/consent detail when it improves entity scanning. Must support long IDs through `long_value`. |
| `pane` | Default structural wrapper for grouped client detail, support detail, and operate queue groups. Do not nest cards inside cards. |
| `workflow_shell` | DCR policy and IAT minting workflow chrome; must not hide `phx-submit`, field names, or validation behavior. |
| `form_field` | Use for DCR fields and IAT fields where practical; help/error IDs must stay deterministic. |
| `status_cluster` | Group badges and small state text in headers and rows; badges wrap without shifting layout. |
| `action_group` | Separate primary, secondary, and destructive actions on client detail and support details. |
| `lifecycle_row` | Use for lifecycle or rotation decisions that need state, actor/time, consequence copy, and actions. |
| `resource_list` | Use for non-tabular lists. Do not place it inside `lockspire-admin-table-wrap`. |
| `dense_resource_row` | Prefer for operate queues and dense support rows that are not comparison tables. |
| `responsive_table` | Use only for real comparison tables that need a narrow list alternative. |
| `confirmation_panel` | Preserve for token and consent revocations; use danger variant for destructive effects. |
| `empty_state` | Must name what is absent and the next safe step. |
| `copy_once_secret_panel` | Only copy-once IAT, RAT, and client-secret states may show plaintext. |
| `long_value` | Required for URLs, IDs, handles, timestamps, scopes, and redacted pivots that can overflow. |

Backward compatibility:

- Preserve current route modules, router entries, LiveView events, form submits, params, field names, and mutation semantics.
- Do not introduce domain workflow components, broad LiveComponents, public component APIs, PhoenixStorybook, a public lab route, or a host-editable registry.
- Stable Phase 109 pages may receive only copy/test alignment when their page job and redaction story are already clear.
